# 🔥 추가 버프 — 계약서

원장 결정 2026-09-22: **오늘부터 고정 ×1.3 + 플래너 최대치 0.4 → 1.0**, 문구는 **C 희망형**, **푸시 알림 보냄**.

## 0. 왜 만드는가

옥길중 중1 시험이 9/30이다. 9월 22일 아침 기준 그 반의 레이드는 **61.1%**,
이대로 가면 **84%**에서 멈춘다. 남은 9일에 힘을 실어야 하는데,

> **「지난날짜의 버프도 올리면 안된다. 남은기간에 열심히 하면 부술 수 있다는 희망을 주어야 한다.」** (원장, 2026-09-21)

기존 버프(`buff.max`)를 올리면 **엔진이 시즌 전체를 매번 다시 세므로 지난 날짜 점수도 함께 올라간다.**
그래서 **날짜를 경계로 나누는** 새 규칙이 필요하다.

## 1. 규칙 — 딱 한 줄

```
그날(d)의 배율
  d <  boost.from  →  1 + (플래너÷10) × buff.max          (지금까지 쓰던 규칙 그대로)
  d >= boost.from  →  boost.flat × (1 + (플래너÷10) × boost.max)
```

- 플래너를 안 올린 날은 괄호 안이 1이므로 `boost.flat` 만 붙는다.
- `boost.from` 은 **한국 날짜** 문자열 `YYYY-MM-DD`. 그날 0시부터다.
- `boost.on` 이 거짓이거나 `boost.from` 이 없으면 **아무 일도 일어나지 않는다**(옛 규칙만).
- `buff.on` 이 꺼져 있으면 추가 버프도 작동하지 않는다. 추가 버프는 기존 버프 «위에» 얹는 것이다.

### 2026-09-22 설정값

| 값 | 무엇 |
|---|---|
| `buff.on` | `true` (그대로) |
| `buff.max` | `0.4` (그대로 — 9/21까지의 점수를 지키기 위해 **절대 건드리지 않는다**) |
| `boost.on` | `true` |
| `boost.from` | `2026-09-22` |
| `boost.flat` | `1.3` |
| `boost.max` | `1.0` |

예: 플래너 0점 → ×1.30 · 7점 → ×2.21 · 10점 → **×2.60**

## 2. 저장 자리

`lumen_store` 키 **`race_season`** 안:

```json
{ "buff": { "on": true, "max": 0.4,
            "boost": { "on": true, "from": "2026-09-22", "flat": 1.3, "max": 1.0 } } }
```

표를 새로 만들지 않는다. 기존 `buff` 안에 `boost` 한 칸만 더한다.

## 3. 같은 규칙을 쓰는 곳 — 셋을 반드시 맞춘다

| 어디 | 함수 |
|---|---|
| 새벽 집계 엔진 | `sync/race_engine.js` → `buffMult(planScore, max, day, boost)` |
| 학원앱 「지금 다시 세기」 | `lumen_v19-29.html` → `rcBuffMult(planScore, max, day, boost)` |
| 학생앱 표시 | 계산하지 않는다 — `race_board.buff` 를 **읽어서 보여 주기만** 한다 |

⚠️ 앞의 둘 중 하나만 고치면 새벽 순위표와 원장님 화면의 숫자가 어긋난다.
두 함수는 **글자까지 같은 계산**이어야 한다.

## 4. 순위표에 실어 보내는 값

`race_board.buff` 를 이렇게 넓힌다 (학생앱·학부모앱이 읽는다):

```json
{ "on": true, "max": 0.4,
  "boost": { "on": true, "from": "2026-09-22", "flat": 1.3, "max": 1.0,
             "dday": 8, "to": "2026-09-30" } }
```

`dday`·`to` 는 엔진이 채운다(시즌 끝나는 날 기준). 학생앱은 이걸로 「남은 8일」을 띄운다.

## 5. 학생앱 문구 — C 희망형 (원장 결정)

홈 맨 위와 레이드 화면에 띠 하나. **버프가 꺼져 있으면 아무것도 나오지 않는다.**

```
[추가 버프 발동 · 남은 8일]
아직 부술 수 있다
보스 체력 17,511 남음.
지금부터는 점수가 ×1.3, 플래너까지 올리면 ×2.6.
[오늘 우리 반 몫 1,946 →]
```

- 숫자(남은 체력 · 오늘 몫 · 남은 날)는 `raid_board` 에서 **매일 자동으로** 바뀐다.
- 체력바 위에 「버프 없이 가면 여기서 멈춘다」는 **노란 선**을 함께 그린다.
- 레이드에 속하지 않은 학생에게는 배수만 보여 주고 체력 이야기는 하지 않는다.

## 6. 푸시 알림 (원장 결정 — 보냄)

- **하루 한 번, 밤 9시(KST).** 버프 기간(`boost.from` ~ 시즌 끝) 동안만.
- 받는 사람: 레이드에 속한 학생 중 푸시를 켠 사람.
- 그날 **플래너를 아직 안 올린 학생**에게는 「버프가 3시간 남았어요」,
  올린 학생에게는 그날 들어간 피해와 남은 체력을 알린다.
- 시즌이 끝나거나 `boost.on` 이 꺼지면 **저절로 멈춘다**.

## 7. 손대지 않는 것

- 9/21까지의 점수·등수·리그 — `boost.from` 이전 날짜는 계산이 한 글자도 바뀌지 않는다
- `buff.max` 값 (0.4 그대로)
- 레이드 체력(`hp`)·기간·대상 학년
- 할 일 보드 점수(`todoPts`)·플래너 승인 방식
- `parent.html`

## 8. 확인 방법

1. `boost.from` 이전 날짜의 피해가 **켜기 전과 1점도 다르지 않은지** (가장 중요)
2. `boost.from` 이후 날짜가 `flat × (1 + 플래너÷10 × boost.max)` 로 계산되는지
3. 엔진과 학원앱 계산기가 **같은 값**을 내는지 (같은 날짜·같은 플래너 점수로)
4. `boost.on=false` 로 두면 켜기 전과 완전히 같은 순위표가 나오는지
5. 학생앱 띠가 버프 꺼짐일 때 안 나오고, 켜짐일 때 숫자가 맞는지
6. 기존 화면(리그·상금·할 일 보드 점수)이 그대로인지
