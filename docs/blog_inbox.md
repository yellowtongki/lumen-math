# 블로그 글감 전달함 (다른 세션 → 블로그 세션)

학원앱 세션이나 다른 채팅에서 **「이건 블로그 글이 되겠다」** 싶은 것이 나오면 여기에 적는다.
블로그 세션이 `git fetch` 해서 읽고 글로 만든다.

## 적는 법

맨 아래에 항목 하나를 덧붙이고 **main 에 push** 한다. 블로그 세션이 알아서 집어 간다.

```
## [대기] 제목 한 줄
- **언제**: 2026-11-16
- **무엇**: 한두 문장. 무슨 일이 있었고 왜 글이 되는지
- **숫자**: 확인된 것만. 없으면 「없음」
- **사진**: 있으면 어디에 있는지 (원장님이 따로 주실 것이면 「원장님」)
- **주의**: 쓰면 안 되는 것이 있으면 적는다
```

글이 완성되면 블로그 세션이 `[대기]` → `[완료 → blog/<폴더>]` 로 바꾼다.

## ⚠️ 여기 적으면 안 되는 것 (공개 저장소다)

- **학생 이름·학생 코드·개별 점수** — 적지 않는다. 「옥길중 3학년 한 명」 처럼만 쓴다
- 학부모 연락처·대화 내용
- 외부 서비스 이름(매쓰플랫·수학비서·클래스바이) — 글에도 못 쓰므로 여기서부터 바꿔 적는다
- 학교 기출 관련 표현 — 「루멘수학 시험대비자료」 로 바꿔 적는다

> 학생 기록의 **숫자가 필요하면 적지 말고 비워 두면 된다.** 블로그 세션이 Supabase(`or_studentdb`,
> `submissions_<코드>`, 플래너 등)에서 직접 읽는다. 누구인지만 알려주면 된다
> (예: 「8월 18일 등록한 옥길중 3학년」).

## [대기] 루멘 클리닉반 개설 — 테스트 → 당일 오답 → 원장 직강
- **언제**: 2026-11-28
- **무엇**: 월·수·금 저녁 + 토요일 오전에 「클리닉반」을 새로 연다. 매 수업이 짧은 테스트(15분) → 그날 바로 오답 정리 → 원장 직강으로 돌아간다. 기존 「리커버리 수업」(틀린 문제를 0개가 될 때까지 다시 푸는 제로테스트)과 다른 점은 **원장이 개념을 직접 다시 설명하는 티칭 시간이 더 들어간다**는 것. 클리닉으로 개념을 잡은 뒤 리커버리 제로테스트로 한 번 더 확인하는 구조. 「모르는 채로 넘어가지 않게, 그날 배운 것은 그날 정리한다」가 글의 중심. 원장 메모: 앞으로 개념 영상 + 클리닉 방식으로 넓혀 갈 첫 단계(이건 글에 «예정»으로만, 단정하지 않기)
- **숫자**: 월·수·금 18:00~19:30, 토 09:00~10:30 · 매일 테스트 15분, 수요일은 주간테스트 · 수강료는 글에 넣을지 원장님께 확인(안내문 기준 월 32만 원)
- **사진**: 원장님
- **주의**: **「하위권」「보충」「부족한 학생」 같은 표현 절대 금지.** 인원수·소수정예 표현도 빼기(원장 지시). 학생 이름·점수 쓰지 않기(오늘 진단 테스트를 본 신규생이 계기지만 언급하지 않음). 영상수업은 아직 준비 단계라 「곧 시작」처럼 쓰지 않기. 외부 채점 서비스 이름 쓰지 않기
