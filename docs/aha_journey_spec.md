## 1-2. 1단계 구현 완료 (2026-09-08, 오퍼스)

만든 것: `student_v2-71.html`(배포 안 함) · `lumen_v18-155.html`(배포) · `supabase/functions/aha-read/index.ts` · `docs/edge_function_deploy.md`

**AI 읽기를 부르는 자리** — 학생앱은 공개 파일이라 Claude 키를 넣을 수 없다. 그래서 읽기만 **Supabase Edge Function `aha-read`**가 대신한다(키는 Supabase Secrets `ANTHROPIC_API_KEY`에만 있다). 배포 안내는 `docs/edge_function_deploy.md`(원장용, 클릭만).
**함수가 없어도 앱은 돈다** — 학생앱은 「선생님이 읽어 드립니다」로 안내하고 사진만 올린다. 원장이 학원앱 채점 패널의 **🤖 사진 다시 읽기**(`or_api_key`로 직접 호출)를 누르면 같은 결과가 나온다. 즉 Edge Function은 **학생 대기시간을 줄이는 선택 사항**이다.

## 2. 1단계 범위 — 「묻기 + 스스로 해결 + 질문력 채점」

### 2-1. 학생앱 (`student_v2-71.html`, 고정 주소 `student_v1.html`은 원장만 교체)

화면 순서(미리보기 ①~⑥와 같음): **① 시작 → ② ⓘ IB 설명 → ③ 사진 → AI 읽기 → 확인 → ④ 스스로 해결 → ⑤ 점수 → ⑥ 리그(5단계)**

**① 시작 화면** (기존 아하노트 탭 첫 화면 개편, 이름 「IB아하노트」)
1. 큰 버튼 하나: **「📷 활동지 사진 찍기」** (카메라/갤러리). 그 아래 한 줄 안내: 「학원에서는 LAMP 활동지에, 집에서는 공책에 L·A·M·P 제목을 쓰고 찍으세요」.
2. **ⓘ IB아하노트란?** 링크 → ② 화면. 아래는 **내 IB아하노트 목록**(카드마다 교재·쪽·번호, 질문력 「임시/확정」 배지, 해결 경로, 상태).
3. **앱에서 글로 직접 쓰는 길은 없다**(D7). 옛 제출 화면의 textarea·한 줄 메모는 없앤다. 옛 노트(memo만 있는 것)는 목록에서 그대로 보인다.

**② ⓘ IB아하노트란? 화면** (읽기만, 문구는 미리보기 그대로 — 원장 확인 후 고정)
- IB(국제 바칼로레아)가 무엇인지 두 줄 · LAMP 다섯 칸이 IB가 수학에서 보는 다섯 가지(이해·원리·논리·질문·성찰)와 같다는 표 · 점수(질문력 10점 + 보너스)와 등급(질문자→탐구자→사고자→성찰자) · 「부모님께」 한 줄. 학부모앱에도 같은 문구를 나중에 쓴다.

**③ 사진 → AI 읽기 → 확인 화면**
1. 사진 1장 필수(활동지 또는 공책). 찍자마자 **AI 읽기**(Haiku 비전, 프롬프트 §4-1)가 돈다. 읽는 동안 「읽는 중…」 표시(보통 5~10초).
2. AI가 채우는 것: 교재/프린트·쪽·번호·틀린이유(활동지 머리) · **L·A·M·P 네 칸 글자** · (있으면) 재풀이·AHA 칸. 결과를 `lamp_ai`에 원본 그대로 저장하고, 각 칸을 학생이 보는 확인 카드에 넣는다.
3. 학생은 **확인·고치기만**: 칸마다 AI가 읽은 글자가 보이고, 잘못 읽은 곳만 탭해서 고친다. **못 읽은 칸(빈 칸·「?」)만 손으로 채우라고 노란 테두리**로 표시. 활동지에 안 쓴 칸(예: A 비움)은 비운 채 두어도 된다(그 칸은 0점).
4. 학생이 앱에서 **고르는 것**: **반응지시어 칩 7개 중 하나**(필수, 표 3-2 뜻풀이 한 줄). 지시어를 고르면 P의 질문 문장 끝에 「~해 주세요」 꼬리를 제안. 옛 「틀린 이유」 칩 5종은 AI가 읽어 온 값을 표시만 하고 고칠 수 있게 둔다.
5. **개념 칩 12** (표 3-1)는 1단계에서 **AI가 추천한 칩 최대 3개를 켜 놓고** 학생은 끄기만(부담 줄이기). 추천은 §4-1 출력의 `concepts`.
6. **자기평가 체크 4칸** (L·A·M·P, 선택 — 접혀 있음): 펼치면 「내가 보기에 잘 쓴 칸」 체크 → 「내 예상 질문력 N」. 서버 `self_eval` 저장(확정 점수와 ±1이면 +1). 원장이 「빼자」 하면 이 항목만 삭제.
7. **질문 유형 자동 태그**(규칙, 표 3-3)와 **질문력 미터**(규칙, 표 3-4)는 확인 카드 아래 작게. 미터는 AI가 읽은 글자 기준이라 「임시」 표시.
8. 버튼 두 개 나란히: **「질문 보내기」** → `status:'pending'` · **「🙋 쓰다 보니 알았어요」** → ④ 화면.

**④ 스스로 해결 화면** (타이머 없음)
- 어떻게 풀렸나(필수, 300자) · 재풀이 사진(필수 — 활동지 6단계 칸을 다시 찍거나 공책) · 되돌아보기(배운 점 / 궁금한 점, 각 선택). AI가 재풀이 사진에서 AHA 칸도 읽어 채운다 → `self_solved` + `reflect`, `status:'self_pending'`. 정답 대조는 학원앱/워커가 함(2-2).

**⑤ 점수 화면 / 개인 기록 카드**
- 제출 직후 **임시 질문력**(규칙 미터 값, 「임시」 배지) → AI 초안이 오면 임시 값 갱신 → 원장 확정 시 「확정 ✓」 + L·A·M·P·AHA 각 점수 + 코치 두 줄(피드백·피드포워드) + 성취수준 A~E 사다리 위치 + 보너스(해결 경로·유형·자기평가 일치).
- **성취수준 A~E 칸 나누기**(2026-09-08 구현): 성취평가제와 같은 기준 — A 9점 이상 · B 8 · C 7 · D 6 · E 5 이하. 미리보기의 「질문력 7 → C」와 같다.
- **힌트 열람 단계 서버 기록**: 기존 로컬 `aha_hint_open_<id>` 외에 `aha_notes.hints_opened`(1·2·3 최대값) 갱신. 재풀이 제출 시 해결 경로가 여기서 결정된다.
- 재풀이 제출(힌트 흐름)에서도 사진 한 장 → AI가 AHA 칸을 읽는다(직접 입력 없음, 못 읽으면 그 칸만 손으로).

**⑥ 🏆 리그 화면** — 미리보기만(코딩은 5단계). 화면 구성: 내 등급(학습자상)·순위·시즌 점수·평균 질문력·스스로 해결 횟수·이번 주 인정 n/8 · 다음 등급 조건 · 순위표(성+○○, 공개 인원 규칙은 레이스와 동일) · 이번 주 베스트 질문 · 규칙 한 줄. 1단계에서는 개인 기록 카드에 「리그는 곧 열려요」 자리만.

※ `timer_used`·`q_guess` 칸은 테이블에 있으나 **쓰지 않는다**.

### 3-2. 반응지시어 7 (경기 논술형 평가 9쪽 뜻풀이 원문)
| 지시어 | 뜻풀이 |
|---|---|
| 설명하시오 | 구체적인 사례를 들어 용어를 정의한다. |
| 비교하시오 | 두 개 이상의 대상에서 공통점(혹은 유사점)과 차이점을 드러내서 진술한다. |
| 논증하시오 | 주장에 대해 이유와 근거를 들어 설명한다. |
| 추론하시오 | 이미 알고 있는 또는 확인된 정보로부터 논리적 결론을 도출한다. |
| 적용하시오 | 주어진 문제 상황에 지식, 이해(원리, 이론, 법칙 등)를 사용한다. |
| 해석하시오 | 지식을 이용하여 주어진 정보의 흐름을 파악하고 결론을 내린다. |
| 평가하시오 | 발상이나 의견의 상대적 중요성을 평가하고 판단한다. |
학생앱 표시는 「설명해 주세요」처럼 부드럽게, 저장은 `설명|비교|…`.

### 3-3. 질문 유형 자동 태그 (규칙, P의 질문 문장 `q_ask` 기준)
- 논쟁적(debate): `꼭|반드시|항상|정말|다른 방법|~해야 하나|~해도 되나|아니면|왜 굳이|더 나은` 중 하나
- 개념적(concept): 위가 아니고 `왜|어째서|이유|어떻게|무슨 차이|차이|관계|원리` 중 하나
- 사실적(fact): 그 외
- Haiku 채점 시 유형을 다시 판정해 다르면 AI 판정을 우선하되, 확정은 원장.

### 3-4. 질문력 미터 규칙 (확인 화면 미리보기, AI 아님 — AI가 읽어 온 글자에 적용)
- **L** 문제 이해: `q_learn`에 「구하」·「조건」·「주어진」 중 하나 + 20자 이상 2 / 15자 이상 1 / 0
- **A** 이론·공식: `q_act`에 15자 이상이고 공식·정리·성질 이름으로 보이는 낱말 포함 2 / 10자 이상 1 / 0
- **M** 풀이 논리: `q_try`에 숫자·`=`·`x`·`y` 등 식 기호 포함 2 / 20자 이상 1 / 0
- **P** 막힌 곳·질문: `q_stuck`에 `단계|줄|번째|에서|부터|까지|계산|대입|식` 포함 **그리고** 지시어 선택 + `q_ask` 끝이 `?|요` 2 / 둘 중 하나만 1 / 0
- 이 값은 「임시」 표시용이며 확정 점수는 AI 초안 → 원장.

## 4-1. Haiku 활동지 읽기 프롬프트 (초안, 비전 — 학생앱 ③ 화면에서 호출)

입력: 활동지(또는 공책) 사진 1장. 모델 `claude-haiku-4-5-20251001`(이미지 입력).
**구현 위치(2026-09-08)**: `supabase/functions/aha-read/index.ts`. 학생앱은 `sb.functions.invoke('aha-read', {body:{photo_url, mode}})`로 부른다. `mode:'retry'`면 재풀이 사진에서 `retry`·`answer`·`aha`만 읽는다. 함수는 우리 Storage 공개 주소만 받아 온다(아무 주소나 대신 받지 않게). 학원앱 쪽 같은 프롬프트는 `ibqReadPhoto()`가 `or_api_key`로 직접 호출한다.
```
사진은 루멘수학 「LAMP 활동지」 또는 학생 공책이다. 연필 손글씨를 읽어 JSON으로만 답한다.
칸: 머리(교재/프린트 이름 book, 쪽 page, 번호 num, 틀린이유 reason: 계산실수|개념부족|문제해석|시간부족|기타),
L(문제 이해) A(이론·공식) M(풀이 논리) P(막힌 곳과 질문) retry(6단계 재풀이, 있으면) aha(7단계 AHA, 있으면).
규칙: 쓴 그대로 옮긴다(맞춤법 고치지 않음). 식은 x^2, 1/2, √ 처럼 한 줄로. 못 읽는 낱말은 「?」로 두고
빈 칸은 ""로. 읽지 못한 칸 이름을 unread 배열에 넣는다. 활동지가 아니라 공책이면 L·A·M·P 제목을 찾아 같은 규칙으로.
concepts: 표 3-1의 영문 키 중 이 문제와 가장 관련 있는 것 최대 3개.
출력: {"book":"","page":null,"num":"","reason":"","L":"","A":"","M":"","P":"","retry":"","aha":"","concepts":[],"unread":[]}
```
결과는 `lamp_ai`에 원본 저장. 학생 확인 후 `q_learn=L, q_act=A, q_try=M, q_stuck+q_ask=P(문장 분리: 마지막 물음표 문장이 q_ask)`, `reflect.learned=aha`로 옮긴다.

## 4. Haiku 질문력 채점 프롬프트 (초안)

입력: 확인이 끝난 LAMP 4칸 텍스트(`q_*`), 지시어, 교재·쪽·번호, (있으면) AHA. 채점은 텍스트만으로(사진은 원장이 카드에서 봄).
```
너는 루멘수학 원장을 돕는 조교다. 학생이 쓴 수학 질문을 아래 5기준으로 채점하고 코치 두 줄을 쓴다.
기준(각 0·1·2): L 문제 이해(구하려는 것과 조건을 자기 말로 정리 2 / 문제를 옮겨 적기만 1 / 없음 0)
A 이론·공식(이 문제에 쓸 이론·공식을 옳게 떠올림 2 / 관련은 있으나 부정확 1 / 없음 0)
M 풀이 논리(어디까지 어떤 순서로 풀었는지 식으로 2 / 「풀어봤는데」 정도 1 / 없음 0)
P 막힌 곳·원하는 것(어느 단계·어느 줄인지 특정 + 지시어가 들어간 한 문장 질문 2 / 둘 중 하나만 1 / 「모르겠어요」 0)
AHA 되돌아보기(못 떠올린 발상 + 배운 점·원리 2 / 하나만 1 / 없음 0 — 입력이 없으면 null)
질문 유형: fact(답이 뭐예요) / concept(왜·어떻게) / debate(꼭 그래야 하나·다른 방법)
코치: fb(피드백) = 잘 쓴 부분을 학생 문장을 인용해 한 문장 인정. ff(피드포워드) = 「다만 ~」으로 시작해 다음 질문에서 고칠 것 하나만, 구체적으로. 모든 문장 「~합니다」체, 「~요」 금지. 각 60자 이내.
출력 JSON만: {"L":2,"A":1,"M":2,"P":2,"AHA":null,"type":"concept","fb":"...","ff":"..."}
```
