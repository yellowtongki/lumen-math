## 1. 점수 체계 (전 단계 공통)

한 아하노트(여정 한 편)에서 쌓이는 점수:

| 항목 | 점수 | 단계 |
|---|---|---|
| 질문력 = **L** 문제 이해 + **A** 이론·공식 + **M** 풀이 논리 + **P** 막힌 곳·원하는 것 + **AHA** 되돌아보기 (각 0·1·2) | 0~10 | 1 |
| 질문 유형 가점 (개념적 +1, 논쟁적 +1) | 0~2 | 1 |
| 해결 경로 보너스 (스스로 4 / 힌트1 3 / 힌트2 2 / 힌트3·손풀이 1) | 0~4 | 1 |
| 자기평가 일치 보너스 (학생 예상 질문력 = 확정 질문력 ±1) | +1 | 1 |
| ⭐ 수업 공통질문 채택 +2 · 🏆 이번 주 베스트 질문 +3 | 0~5 | 1 |
| 원리 한 문장(일반화) +2 · 전이 문제 +1 · 내가 문제 만들기 4항목 0~4 · 갤러리 풀림 +1/회 | | 3 |
| 🎙 그 문제 녹음 설명(완결) +2 | | 5 |
| AI 오류 찾기 (선택) 쉬운 +2 / 어려운 +4 | | 4 |

- 리그 인정 상한: **하루 2건, 주 8건** (질문력 5 미만은 리그 0점, 개인 기록에는 남김).
- 등급(학습자상): 시즌 평균 질문력 + 조건. 질문자(기본) → 탐구자(평균 6 이상·인정 5건) → 사고자(평균 8 이상·스스로 해결 3회) → 성찰자(되돌아보기 10건·녹음 설명 3회). 강등 없음. 문턱은 시즌 설정에서 조정 가능.

## 2. 1단계 범위 — 「묻기 + 스스로 해결 + 질문력 채점」

### 2-1. 학생앱 (`student_v2-71.html`, 고정 주소 `student_v1.html`은 원장만 교체)

**질문 작성 화면(기존 아하노트 제출 화면 개편)**
1. 기존 필수: 사진 1장 · 출처(교재/프린트) · 쪽·번호 — 그대로.
2. 기존 「틀린 이유」 칩 5종 — 그대로 (선택).
3. **개념 칩 12** (선택, 복수): 표 3-1의 중학생 말로 표시, 칩 아래 작은 글씨로 IB 용어.
4. **LAMP 4칸** (textarea, 각 최대 300자) — 종이 활동지와 같은 이름·같은 순서:
   - **L** Learn the question (문제를 정확히 이해하기) — 구하려는 것과 문제 조건 → `q_learn`
   - **A** Activate Knowledge (관련 이론·공식 떠올리기) → `q_act`
   - **M** Model your reasoning (어떻게 풀었나요? 어떤 논리로?) → `q_try`
   - **P** Pinpoint your confusion (막힌 곳을 콕 집고 질문 정리) → `q_stuck` + `q_ask`
   - P 칸 안에 **반응지시어 칩 7개**(단일 선택). 칩을 누르면 뜻풀이 한 줄 표시(표 3-2). 지시어를 고르면 질문 문장 끝에 「~해 주세요」 꼬리를 자동 제안.
   - 기존 「한 줄 메모」는 `q_ask`로 흡수(옛 노트의 memo는 그대로 보존·표시). `q_guess`는 쓰지 않는다.
5. **질문 유형 자동 태그** (규칙 기반, 표 3-3): P의 질문 문장(`q_ask`) 입력 중 실시간으로 「사실적 / 개념적 / 논쟁적」 태그 표시.
6. **질문력 미터** (규칙 기반 미리보기, 표 3-4): LAMP 4칸 채움 정도로 0~8을 즉시 계산해 막대 표시. AHA는 해결 후 채우므로 작성 시점 최대 8.
7. **자기평가 체크 4칸** (L·A·M·P, AHA는 해결 후라 비활성): 학생이 스스로 체크 → 「내 예상 질문력 N」. 서버에 저장(확정 점수와 비교해 +1).
8. **스스로 해결 패널** (「🙋 쓰다 보니 알았어요」): 질문 보내기 버튼 **옆에 나란히** 둔다(타이머 없음). 어떻게 풀렸나(필수, 300자) · 재풀이 사진(필수) · 되돌아보기(배운 점 / 궁금한 점, 각 선택) → `status:'self_pending'`으로 저장. 정답 대조는 학원앱/워커가 함.
9. 제출 후 노트 카드에 **임시 질문력**(규칙 기반 미리보기 값, 「임시」 배지) 표시 → 확정 시 「확정 ✓」 + 확정 점수 + LAMP 문자 결과(예: 「L·M·P ✓ / A △ / AHA ○」) + 코치 두 줄(피드백·피드포워드).
10. **힌트 열람 단계 서버 기록**: 기존 로컬 `aha_hint_open_<id>` 외에 `aha_notes.hints_opened`(1·2·3 최대값)를 갱신. 재풀이 제출 시 해결 경로가 여기서 결정된다.
11. 재풀이 제출 화면에 **AHA 칸**(어떤 발상을 못 떠올렸나 / 궁금한 점) 추가 — AHA 점수 근거. 종이 활동지의 7단계와 같은 칸.

※ `timer_used` 칸은 이미 테이블에 만들어져 있으나 **쓰지 않는다**(항상 false). 나중에 필요해지면 그때 쓴다.

**개인 기록 화면(기존 아하노트 목록)**: 노트마다 질문력·유형 태그·해결 경로·상태 배지. 리그 보드는 5단계에서.

### 2-2. 학원앱 (`lumen_v18-155.html`, `lumen_v1.html` 함께 교체)

**아하노트 카드 안 「질문력 채점」 패널** (힌트 발송 팝업과 같은 자리)
1. LAMP 4칸·지시어·유형·개념 칩·자기평가를 카드에 표시.
2. **AI 초안**: Haiku(`claude-haiku-4-5-20251001`)가 L·A·M·P·AHA 각 0·1·2 + 코치 두 줄 초안(프롬프트 §4). 노트가 들어오면 자동 생성(새벽 워커 또는 카드 열 때 1회), `aha_scores`에 `status:'temp'`로 저장 → 학생앱에 임시 점수로 즉시 노출.
3. 원장 조정: L·A·M·P·AHA 항목별 0/1/2 버튼, 코치 두 줄 편집, 「확정」 버튼 → `status:'final'`, `+1 자기평가 일치` 자동 계산.
4. 버튼: 「💡 힌트 + 점수 함께 발송」(기존 hntSend에 점수 확정 동봉) · 「⭐ 수업 공통질문 채택 +2」(v18-151 공통 질문과 연결) · 「🏆 베스트 질문 후보」.
5. 일괄: 수업 모드(v18-150) 목록에서 여러 노트를 골라 「AI 초안 그대로 확정」 일괄 버튼.

**스스로 해결 확인 카드** (`status:'self_pending'`)
1. 학생 설명 · 재풀이 사진 · 되돌아보기 표시.
2. **정답 대조**: 교재 정답사전(`book_answers`, 수집기 --bookans)에 답이 있으면 AI(Haiku)가 사진에서 최종 답을 읽어 대조 → 일치 ✓ / 불일치 ✗ / 사전 없음 표시. 불일치면 자동으로 「힌트 흐름으로」 제안.
3. 버튼: 「✓ 확인(보너스 +4 확정)」 · 「✏️ 점수 조정」 · 「🏆 스스로 해결 이야기에 올리기」 · 「↩ 아직 아님 → 힌트 흐름으로」.
4. 확인 전에도 학생앱에는 「임시 +4 (확인 대기)」로 표시. 정답 불일치·설명 없음이면 임시 점수 미표시.

### 2-3. 데이터

**`aha_notes` 테이블 새 컬럼** (SQL: `docs/aha_journey.sql`, 모두 nullable — 옛 노트 호환)
```
q_learn text, q_act text,   -- ★ 2026-09-07 추가 (LAMP의 L·A)
q_try text, q_stuck text, q_guess text, q_ask text,   -- q_try=M · q_stuck+q_ask=P · q_guess 미사용
directive text,            -- 설명|비교|논증|추론|적용|해석|평가
q_type text,               -- fact|concept|debate
concepts text[],           -- IB 용어 영문 키 (change, equivalence, generalization, validity, approximation, model, pattern, quantity, representation, simplification, space, system)
self_eval jsonb,           -- {L:0|1, A, M, P, expected:int}
self_solved jsonb,         -- {how:text, photo_url, at, reflect:{learned,wonder}}
hints_opened int default 0,
reflect jsonb,             -- {learned, wonder, at}  (재풀이 제출 시)
timer_used boolean default false
```
`status` 값 추가: `self_pending`(스스로 해결 확인 대기). 기존 pending/resolved 유지.

**`lumen_store` 새 키** (메인 동기화와 분리, pwa_index 패턴)
- `aha_scores` = `{ byId: { [noteId]: { L,A,M,P,AHA, total, typeBonus, pathBonus, selfMatch, pick, best, status:'temp'|'final', coach:{fb, ff}, path:'self'|'h1'|'h2'|'h3'|'hand'|'none', at, by } } }`
- 학생앱은 `aha_scores`를 읽기만(자기 코드 노트만 표시).

### 3-1. 개념 칩 12 (중학생 말 → IB 용어)
| 키 | 표시 | IB 용어 |
|---|---|---|
| change | 변하는 양 | 변화 |
| equivalence | 같은 값 다른 모양 | 동치성 |
| generalization | 규칙 찾기 | 일반화 |
| validity | 맞는지 따지기 | 타당성 |
| approximation | 어림 | 근사 |
| model | 식으로 나타내기 | 모델 |
| pattern | 패턴 | 패턴 |
| quantity | 양·개수 | 수량 |
| representation | 표·그래프·식 바꾸기 | 표현 |
| simplification | 간단히 하기 | 단순화 |
| space | 도형·공간 | 공간 |
| system | 여러 조건 한꺼번에 | 시스템 |

### 3-2. 반응지시어 7 (경기 논술형 평가 9쪽 뜻풀이 원문)
| 지시어 | 뜻풀이 |
|---|---|
| 설명하시오 | 구체적인 사례를 들어 용어를 정의한다. |
| 비교하시오 | 두 개 이상의 대상에서 공통점(혹은 유사점)과 차이점을 드러내서 진술한다. |
| 논증하시오 | 주장에 대해 이유와 근거를 들어 설명한다. |
| 추론하시오 | 이미 알고 있는 또는 확인된 정보로부터 논리적 결론을 도출한다. |
| 적용하시오 | 주어진 문제 상황에 지식, 이해(원리, 이론, 법칙 등)를 사용한다. |
| 해석하시오 | 지식을 이용하여 주어진 정보의 흐름을 파악하고 결론을 내린다. |
| 평가하시오 | 발상이나 의견의 상대적 중요성을 평가하고 판단한다. |
학생앱 표시는 「설명해 주세요」처럼 부드럽게, 저장은 `설명|비교|…`.

### 3-3. 질문 유형 자동 태그 (규칙, P의 질문 문장 `q_ask` 기준)
- 논쟁적(debate): `꼭|반드시|항상|정말|다른 방법|~해야 하나|~해도 되나|아니면|왜 굳이|더 나은` 중 하나
- 개념적(concept): 위가 아니고 `왜|어째서|이유|어떻게|무슨 차이|차이|관계|원리` 중 하나
- 사실적(fact): 그 외
- Haiku 채점 시 유형을 다시 판정해 다르면 AI 판정을 우선하되, 확정은 원장.

### 3-4. 질문력 미터 규칙 (작성 화면 미리보기, AI 아님)
- **L** 문제 이해: `q_learn`에 「구하」·「조건」·「주어진」 중 하나 + 20자 이상 2 / 15자 이상 1 / 0
- **A** 이론·공식: `q_act`에 15자 이상이고 공식·정리·성질 이름으로 보이는 낱말 포함 2 / 10자 이상 1 / 0
- **M** 풀이 논리: `q_try`에 숫자·`=`·`x`·`y` 등 식 기호 포함 2 / 20자 이상 1 / 0
- **P** 막힌 곳·질문: `q_stuck`에 `단계|줄|번째|에서|부터|까지|계산|대입|식` 포함 **그리고** 지시어 선택 + `q_ask` 끝이 `?|요` 2 / 둘 중 하나만 1 / 0
- 이 값은 「임시」 표시용이며 확정 점수는 AI 초안 → 원장.

## 4. Haiku 질문력 채점 프롬프트 (초안)

입력: LAMP 4칸 텍스트, 지시어, 사진 없음(텍스트만), 교재·쪽·번호, (있으면) AHA.
```
너는 루멘수학 원장을 돕는 조교다. 학생이 쓴 수학 질문을 아래 5기준으로 채점하고 코치 두 줄을 쓴다.
기준(각 0·1·2): L 문제 이해(구하려는 것과 조건을 자기 말로 정리 2 / 문제를 옮겨 적기만 1 / 없음 0)
A 이론·공식(이 문제에 쓸 이론·공식을 옳게 떠올림 2 / 관련은 있으나 부정확 1 / 없음 0)
M 풀이 논리(어디까지 어떤 순서로 풀었는지 식으로 2 / 「풀어봤는데」 정도 1 / 없음 0)
P 막힌 곳·원하는 것(어느 단계·어느 줄인지 특정 + 지시어가 들어간 한 문장 질문 2 / 둘 중 하나만 1 / 「모르겠어요」 0)
AHA 되돌아보기(못 떠올린 발상 + 배운 점·원리 2 / 하나만 1 / 없음 0 — 입력이 없으면 null)
질문 유형: fact(답이 뭐예요) / concept(왜·어떻게) / debate(꼭 그래야 하나·다른 방법)
코치: fb(피드백) = 잘 쓴 부분을 학생 문장을 인용해 한 문장 인정. ff(피드포워드) = 「다만 ~」으로 시작해 다음 질문에서 고칠 것 하나만, 구체적으로. 모든 문장 「~합니다」체, 「~요」 금지. 각 60자 이내.
출력 JSON만: {"L":2,"A":1,"M":2,"P":2,"AHA":null,"type":"concept","fb":"...","ff":"..."}
```
