# 교재 키패드 자동채점 — 상세 계획

작성 2026-08-19 · 대상 초6~중2 · 부정(자가 O/X) 방지가 목적
정찰·채점엔진 시제품 검증 완료 후 작성. **아직 코딩 전 — 이 문서로 원장님 확인.**

---

## 0. 왜 만드나 (한 줄)

지금 시중교재(RPM 등)는 학생이 **O/X를 스스로 체크**해서 틀린 걸 맞았다고 할 수 있다.
→ **학생이 답을 키패드로 입력하게 하고, 앱이 매쓰플랫 정답과 대조**해 자동채점한다.
긴 서술형·도형은 **원장님이 직접 채점**한다.

## 0-1. 채점 결과 처리 = ⓑ 매쓰플랫에 되돌려쓰기 (원장님 결정 2026-08-19)

채점은 우리 앱에서 하되, 그 **O/X 결과를 매쓰플랫에 다시 기록**한다.
→ 새벽 수집이 그대로 가져와서 **리포트·리커버리·진도·취약유형 등 기존 기능이 하나도 안 바뀌고** 자동 반영된다.
매쓰플랫이 계속 「하나의 원본」으로 남는다.

- 통로 확인됨: `PATCH /student-workbook/scoring` (mp_event=교재문제채점, version v2)
- ⚠️ **본문(어떤 필드로 보내는지)은 실제 채점 화면 통신을 봐야 확정** — 코드 번들엔 endpoint만 있고 body 구성은 없음
- ⚠️ **되돌려쓰기 안전성은 「1단계」의 첫 관문으로 검증** — 되돌리기 가능한 방식(내 계정/시범 학생 1문항, 쓴 뒤 원복)으로 먼저 확인하고, 안전 확인 전에는 실제 학생 기록에 쓰지 않는다
- 만약 되돌려쓰기가 위험하거나 막히면 → ⓐ(우리 Supabase에만 저장)로 안전하게 후퇴

## 1. 정찰로 확인된 사실 (근거)

| 확인 | 결과 |
|---|---|
| 매쓰플랫에서 교재 페이지 답 조회 | ✅ `GET /workbook/{교재}/page/{페이지}` → 문항+정답 전부 |
| 매쓰플랫 자체 자동채점 | ❌ 교재 주관식은 `autoScoredType: IMPOSSIBLE` (매쓰플랫도 안 함) → **엔진 자체 제작 필요** |
| 채점엔진 시제품 (실제 답 80개) | ✅ 정답 자기일치 100% = **오채점 0건** · 분수 약분·소수·단위·복수답 순서 동치 인식 |
| 초6~중2 자동채점 비율 (112문항) | 객관식 21% + 숫자/분수/소수 43% = **약 64% 자동** · 문자식 14% · 도형/서술 22% |

## 2. 데이터 모델 (Supabase 신규 테이블)

**`mf_book_answers`** — 교재 페이지의 정답 사전
```
book_id            교재 id (매쓰플랫)
page_id            workbook_page_id
book_name          "RPM 중2-1" (표시용)
page_label         "88~92" (표시용)
number             문항번호 "15", "1.(2)"
type               MULTIPLE_CHOICE | SINGLE_CHOICE | SHORT_ANSWER | ESSAY
answer_raw         매쓰플랫 원본 정답 ("72\text{ cm}^3")
answer_norm        엔진이 만든 정규화 정답 (["72"]) — 없으면 null
gradable           true = 앱 자동채점 / false = 선생님 수기
unit               단위 라벨 ("cm³") — 입력칸 옆 표시
option_count       객관식 보기 수
problem_image_url  문제 이미지 (선택 — 약관 검토)
```
- lumen_store 대신 별도 테이블 (문항이 많아 jsonb보다 표가 낫다)
- **약관 주의**: 우리 학생이 실제 배정받은 교재·페이지만 수집. 문제 이미지 재배포는 보류(1단계는 이미지 없이 번호+답만으로도 채점 가능)

## 3. 새벽 수집기 (sync/mathflat_collector.js 확장)

- 신규 함수 `refreshBookAnswers()`
- **배정 교재만**: `mf_study_sessions`(source=교재)에서 우리 학생이 배정받은 (book_id, page) 목록 → 각 페이지 `/workbook/{b}/page/{p}` 조회
- 각 문항을 채점엔진으로 정규화 → `gradable` 판정 → `mf_book_answers` upsert
- 「지금 가져오기」에도 연결 (원장님이 즉시 당길 수 있게)
- 캐시: 같은 페이지는 이미 있으면 건너뜀 (매일 전체 재수집 안 함)

## 4. 채점엔진 (검증된 시제품 → 정식화)

학생앱·수집기 양쪽에서 쓰는 **동일 함수**. 핵심 = `toValue()` + `grade()`.
- 단위 제거: `\text{...}`, 끝 단위문자(cm·층·개), °²³
- 분수: `\frac{a}{b}`, `a/b`, 대분수 → 값 + 기약분수
- 소수: `1.50 = 1.5`, `.02 = 0.02` (앞 0 보정 — 시제품에서 발견한 유일한 미스, 한 줄 수정)
- 복수답: 콤마 분리 후 집합 비교(순서 무관)
- **불변식: 정답 원본을 넣으면 반드시 correct** (오채점 0 유지 — 자동 검증에 포함)
- 못 읽는 답(도형·문자식) → `gradable:false` → 수기채점으로

## 5. 학생앱 (student_v2-40)

- 홈/로드맵에서 「📖 교재 채점」 진입 → 오늘 배정 교재·페이지
- **페이지 단위**: 문항 리스트, 각 문항에 답 입력칸 + 수학 키패드(숫자·−·.·분수·±·⌫)
- **부정 차단의 핵심 = 먼저 입력·나중 공개**: 「제출」 눌러야 정답 공개
  - 객관식·숫자 → 그 자리 ⭕❌ + 정답 표시
  - 도형·서술 → 「✍️ 선생님이 채점할 문제예요」 (학생은 종이에 풀이)
- **「모름(?)」 버튼 = 매쓰플랫과 동일한 3상태 채점** (원장님 요구 2026-08-19)
  - 매쓰플랫 채점값은 실측상 `O`·`X`·`?`·`-`(미채점) 4가지 — 우리도 그대로 씀
  - 학생이 답을 모르면 틀린 답을 찍는 대신 **「모름 ?」**을 눌러 `?`로 기록
  - `?`는 오답(X)과 구분: 틀린 게 아니라 **손도 못 댄 것** → 리커버리·복습·아하노트 유도에 씀
    (기존 숙제체크 종이의 ❓ = 「모르겠다 표시」와 같은 개념, 이미 시스템에 있음)
  - 되돌려쓰기 때 `?`도 그대로 매쓰플랫에 기록
- 결과 저장: 문항별 `result`(O/X/?) + 입력답 + 시각
- XP·보상 없음 (원장님 방침)

## 6. 되돌려쓰기 (ⓑ) — 매쓰플랫에 O/X 기록

- **새벽 수집기(또는 지금가져오기 워커)가** 학생이 채점한 O/X를 `PATCH /student-workbook/scoring`으로 매쓰플랫에 반영
- 비밀번호는 워커만 가지므로, 학생앱은 결과를 lumen_store에 「채점 대기」로 올리고 → 워커가 매쓰플랫에 씀 (「지금 가져오기」와 같은 요청+워커 패턴)
- 도형·서술 수기채점 결과(원장님이 매긴 O/X)도 같은 통로로 반영
- 실패 시 재시도 큐 + 실패 알림 (틀리게 쓰면 안 되므로 보수적으로)

## 7. 학원앱 (lumen_v18-74+)

## 10-1. 큰 방향 — 우리 앱을 「학생용 유일 창구」로, 매쓰플랫 학생앱 접근 차단 (원장님 방침 2026-08-19)

학생은 매쓰플랫 앱을 쓰지 않고 **우리 학생앱에서만 채점**한다. 매쓰플랫은 **선생님 쪽 데이터 저장고**로만 남는다.
```
[선생님] 매쓰플랫에서 교재 배정        (지금과 동일)
[학생]   우리 앱에서 답 입력·자동채점   (매쓰플랫 앱 안 씀)
[워커]   O/X를 매쓰플랫에 되돌려씀      (ⓑ)
[새벽]   수집 → 리포트·리커버리·진도    (지금과 동일)
```
**이 방침의 무게**: 매쓰플랫이 「원본」에서 「하류(우리 앱이 먹여주는 곳)」로 바뀐다.
→ 되돌려쓰기(ⓑ)가 **선택이 아니라 필수·생명선**이 된다. 실패하면 매쓰플랫이 비고 모든 리포트가 깨진다.
→ 그래서 **되돌려쓰기 신뢰성 + 실패 복구**가 이 프로젝트의 최우선 관문. (안 되면 이 방침 자체를 재검토)

### 상의 완료 (2026-08-19)
- **학생이 잃는 매쓰플랫 기능**: ✅ 문제없음 — 재풀이·유사문제 프린트는 **원장님이 직접 만들어 줌**. 학생은 매쓰플랫에서 채점만 하던 것이라 우리 앱으로 옮겨도 손실 없음
- **약관/수집 범위**: ✅ **학생앱(=우리 앱)에 등록된 교재만** 답을 긁어옴. 책 전체를 한꺼번에 긁지 않고 등록된 교재의 도달 페이지만 → 약관 안전
- **전환**: ✅ **한 번에 넘기기** (초6~중2 동시 컷오버 — 섞이는 기간 없음)
- **교재 배정은 계속 매쓰플랫에서**: 선생님이 매쓰플랫에서 배정 → 우리 앱이 그 배정을 읽어 학생에게 표시

## 11-1. 회차(revision) — 처음부터 회차 단위로 (원장님 확인 2026-08-19)

- **매쓰플랫은 회차 완전 지원**: `recentRevisionRound`(회차 번호)·`revisionId`, 채점/조회가 전부 revisionId 단위
  (`/student-workbook/{학생}/{교재}/{revisionId}/{progressId}`). 같은 교재 재출제 → 2·3회차 생성.
- **우리 데이터는 아직 회차 미구분**: mf_answer_records에 revision 컬럼 없음, 같은 문항 재채점 0건 → **미구현**. 이번에 만든다.
- **읽기**: 학생이 몇 회차를 푸는지(recentRevisionRound) 확인 → 그 회차의 문항·진도 표시. 학생앱에 「N회차 | 교재명」
- **쓰기(되돌려쓰기)**: 반드시 **그 회차의 revisionId·progressId**에 O/X 기록 (이전 회차를 덮지 않음)
- **정답 사전은 회차와 무관**: 같은 교재는 회차가 달라도 문항·정답이 같으므로 mf_book_answers는 회차 없이 교재·페이지 단위로 재사용
- 수집기·학생앱·되돌려쓰기 모두 revisionId를 키에 포함

## 11-2. ✅ 되돌려쓰기 API 계약 확정 (2026-08-19 실검증, 원복 완료)

되돌리기 가능한 시범 1문항으로 실제 검증 통과. **읽기 → CORRECT 쓰기 → 확인 → NONE 원복 → 재확인** 모두 성공.

**읽기** (문항·현재채점 조회):
```
GET /student-workbook/student/{studentId}/{studentWorkbookId}/{revisionId}
    → { workbook, round, page:{content:[{progressId, workbookPage, status}...]} }   # 페이지 목록
GET /student-workbook/student/{studentId}/{studentWorkbookId}/{revisionId}/{progressId}
    → [{ id(=workbookProblemId), number, type, answer, autoScoredType, scoring:{...} }...]   # 페이지 문항+채점
    scoring = { studentWorkbookProgressId, workbookProblemId, userAnswer, userAnswers, result, assists, updateDatetime }
```
**쓰기** (채점 되돌려쓰기 — ★ 본문은 「배열 그대로」):
```
PATCH /student-workbook/scoring?version=v2
  body = [ { studentWorkbookProgressId, workbookProblemId, userAnswer, result } ]   # 배열!
  result 값: CORRECT(O) · INCORRECT(X) · NONE(미채점) · (모름 ? 값은 구현 때 확정)
  ※ {studentWorkbookProgressId, scoringList:[...]} / {single obj} 는 400 MESSAGE_NOT_READABLE
```
- ID 얻는 길: 교재목록 `GET /student-workbook/student/{sid}?workbookType=PUBLIC`(시중교재)·SCHOOL(교과서)·CUSTOM(내교재)
  → 교재.studentWorkbook.id = studentWorkbookId, recentRevisionId, roundToRevisionRoundMap(회차별 progressId)
- userAnswer는 200이지만 읽기에 null로 보임 → 구현 때 확인(result 반영은 확실). 모름(?) 결과값도 구현 때 확정.
- **비밀번호는 워커만** → 학생앱은 채점을 lumen_store에 올리고 워커가 이 PATCH 실행 (지금가져오기 패턴)

## 12. 계획 확정 — 착수 대기

위 결정으로 계획이 모두 확정됨. 남은 것은 코딩뿐이며, **원장님 「시작」 지시 대기**.
착수 시 순서(생명선부터):
1. **되돌려쓰기 안전 검증** (되돌리기 가능한 시범 1문항) — 통과해야 나머지 진행. 실패 시 ⓐ로 후퇴
2. 수집기 정답사전(`refreshBookAnswers`) — 등록 교재의 도달 페이지만
3. 채점엔진 정식화 + 자동 검증(오채점 0 불변식)
4. 학생앱 키패드 화면(문항마다 즉시 채점·먼저입력 나중공개)
5. 학원앱 수기채점 큐(도형·서술)
6. 되돌려쓰기 워커 + 실패 복구
→ 학생앱은 순공피드백(v2-38)과 묶어 한 번에 배포

## 11. 검증 계획 (/verify)

- 채점엔진: 실제 답 수백 개로 자기일치 100% 재확인 + 동치 인식 케이스
