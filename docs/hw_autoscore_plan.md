# 교재 키패드 자동채점 — 상세 계획

작성 2026-08-19 · 대상 초6~중2 · 부정(자가 O/X) 방지가 목적
정찰·채점엔진 시제품 검증 완료 후 작성. **아직 코딩 전 — 이 문서로 원장님 확인.**

## 0. 왜 만드나 (한 줄)

지금 시중교재(RPM 등)는 학생이 **O/X를 스스로 체크**해서 틀린 걸 맞았다고 할 수 있다.
→ **학생이 답을 키패드로 입력하게 하고, 앱이 매쓰플랫 정답과 대조**해 자동채점한다.
긴 서술형·도형은 **원장님이 직접 채점**한다.

## 1. 정찰로 확인된 사실 (근거)

| 확인 | 결과 |
|---|---|
| 매쓰플랫에서 교재 페이지 답 조회 | ✅ `GET /workbook/{교재}/page/{페이지}` → 문항+정답 전부 |
| 매쓰플랫 자체 자동채점 | ❌ 교재 주관식은 `autoScoredType: IMPOSSIBLE` (매쓰플랫도 안 함) → **엔진 자체 제작 필요** |
| 채점엔진 시제품 (실제 답 80개) | ✅ 정답 자기일치 100% = **오채점 0건** · 분수 약분·소수·단위·복수답 순서 동치 인식 |
| 초6~중2 자동채점 비율 (112문항) | 객관식 21% + 숫자/분수/소수 43% = **약 64% 자동** · 문자식 14% · 도형/서술 22% |

## 2. 데이터 모델 (Supabase 신규 테이블)

**`mf_book_answers`** — 교재 페이지의 정답 사전
```
book_id            교재 id (매쓰플랫)
page_id            workbook_page_id
book_name          "RPM 중2-1" (표시용)
page_label         "88~92" (표시용)
number             문항번호 "15", "1.(2)"
type               MULTIPLE_CHOICE | SINGLE_CHOICE | SHORT_ANSWER | ESSAY
answer_raw         매쓰플랫 원본 정답 ("72\text{ cm}^3")
answer_norm        엔진이 만든 정규화 정답 (["72"]) — 없으면 null
gradable           true = 앱 자동채점 / false = 선생님 수기
unit               단위 라벨 ("cm³") — 입력칸 옆 표시
option_count       객관식 보기 수
problem_image_url  문제 이미지 (선택 — 약관 검토)
```
- lumen_store 대신 별도 테이블 (문항이 많아 jsonb보다 표가 낫다)
- **약관 주의**: 우리 학생이 실제 배정받은 교재·페이지만 수집. 문제 이미지 재배포는 보류(1단계는 이미지 없이 번호+답만으로도 채점 가능)

## 3. 새벽 수집기 (sync/mathflat_collector.js 확장)

- 신규 함수 `refreshBookAnswers()`
- **배정 교재만**: `mf_study_sessions`(source=교재)에서 우리 학생이 배정받은 (book_id, page) 목록 → 각 페이지 `/workbook/{b}/page/{p}` 조회
- 각 문항을 채점엔진으로 정규화 → `gradable` 판정 → `mf_book_answers` upsert
- 「지금 가져오기」에도 연결 (원장님이 즉시 당길 수 있게)
- 캐시: 같은 페이지는 이미 있으면 건너뜀 (매일 전체 재수집 안 함)

## 4. 채점엔진 (검증된 시제품 → 정식화)

학생앱·수집기 양쪽에서 쓰는 **동일 함수**. 핵심 = `toValue()` + `grade()`.
- 단위 제거: `\text{...}`, 끝 단위문자(cm·층·개), °²³
- 분수: `\frac{a}{b}`, `a/b`, 대분수 → 값 + 기약분수
- 소수: `1.50 = 1.5`, `.02 = 0.02` (앞 0 보정 — 시제품에서 발견한 유일한 미스, 한 줄 수정)
- 복수답: 콤마 분리 후 집합 비교(순서 무관)
- **불변식: 정답 원본을 넣으면 반드시 correct** (오채점 0 유지 — 자동 검증에 포함)
- 못 읽는 답(도형·문자식) → `gradable:false` → 수기채점으로

## 5. 학생앱 (student_v2-40)

- 홈/로드맵에서 「📖 교재 채점」 진입 → 오늘 배정 교재·페이지
- **페이지 단위**: 문항 리스트, 각 문항에 답 입력칸 + 수학 키패드(숫자·−·.·분수·±·⌫)
- **부정 차단의 핵심 = 먼저 입력·나중 공개**: 「제출」 눌러야 정답 공개
  - 객관식·숫자 → 그 자리 ⭕❌ + 정답 표시
  - 도형·서술 → 「✍️ 선생님이 채점할 문제예요」 (학생은 종이에 풀이)
- 결과 저장: `lumen_store book_score_<코드>` 또는 기존 `bookprog_` 확장 (문항별 정오·입력답·시각)
- XP·보상 없음 (원장님 방침)

## 6. 학원앱 (lumen_v18-74+)

- **수기채점 큐**: 도형·서술 문항을 원장님이 O/X. 학생이 낸 답도 같이 표시. 숙제체크 자리 근처
- 문항별 정오 현황 (자동+수기 합산) → 기존 진도/리커버리와 연결
- 채점 결과가 매쓰플랫 O/X와 어긋나면 표시(교차검증)

## 7. 단계

| 단계 | 내용 | 자동채점 |
|---|---|---|
| **1** | 수집기 정답사전 + 채점엔진 + 학생앱 키패드(객관식·숫자) + 학원앱 수기큐 | ~64% |
| **2** | 정규화 강화(단위·특수형) + 수기큐 다듬기 | ~70% |
| **3** | 문자식(3a+2b) 채점 | +14% |

## 8. 배포 방침 (원장님 결정)

- **순공피드백(v2-38)과 교재 채점을 함께 만든 뒤 학생앱을 한 번에 배포** (원장님 지시 2026-08-19)
- 그때까지 student_v1.html(고정 주소)은 v2-37 유지
- 학원앱은 기능 완성마다 그때그때 배포 가능

## 9. 정할 것 (남은 질문)

1. **문제 이미지**: 학생앱에 교재 문제 이미지를 보여줄지 (약관·용량) / 아니면 번호만 보고 종이 교재를 보며 답만 입력할지 → **후자를 권장**(약관 안전, 용량 0, 학생은 종이 교재로 풂)
2. **입력 단위**: 페이지 전체를 한 번에 제출 vs 문항마다 즉시 채점
3. **결과 저장 위치**: 기존 `bookprog_`에 얹기 vs 신규 키
4. **교재 범위**: 초6~중2 전체 vs 특정 교재(RPM·쎈)부터

## 10. 검증 계획 (/verify)

- 채점엔진: 실제 답 수백 개로 자기일치 100% 재확인 + 동치 인식 케이스
- 학생앱: 브라우저에서 키패드 입력→채점, 먼저입력·나중공개 동작, 도형은 수기 표시
- 수집기: Node 직접 실행으로 정답사전 생성 확인
- 학원앱: 수기큐 렌더·저장
