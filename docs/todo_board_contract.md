# 📋 할 일 보드 (칸반) — 계약서

원장 결정 2026-09-20: **발전안 2차 ①부터 진행**. 받음 체크는 **학생·원장 둘 다**,
백지테스트는 **개념 백지 + 틀린 유형 재풀이 둘 다**(②에서), AI 비서는 **카드 올리기까지**(③에서).
학원앱 **v19-26** + 학생앱 **v2-97** 한 벌에 담는다. 학생앱 고정 주소(`student_v1.html`)는 원장님이 판단하신다.

## 0. 왜 만드는가 — 원장님 말씀 그대로

> 칸반보드가 이 학원에서 가장 중요한 기능이었다. 학생들의 할 것들을 순서대로 배정할 수 있고,
> 그것이 학생앱에서 보인다. 학생이 시험지를 받았는지를 체크할 수 있다.
> 이것에 채울 것이 아직 없는 게 우리 학원이 부족한 부분이다. **큰 스케줄을 짜고, 1과에 할 것들을
> 그 보드에 넣어 두면** 학생들은 내가 무엇을 할지가 보이게 된다.
> 그 학원은 영상을 미리 듣는 학원이다. 우리 학원이 앞으로 나아갈 방향이다.

그래서 카드를 하나씩 손으로 올리는 보드가 아니라, **코스(큰 스케줄) → 단원 → 단계** 를 한 번 짜 두면
학생마다 순서대로 카드가 풀려 나가는 보드로 만든다. 단원의 첫 단계는 늘 **📺 개념 영상** 이 올 수 있게 한다.

## 1. 낱말

| 낱말 | 뜻 | 예 |
|---|---|---|
| **코스** | 큰 스케줄. 학년·학기 단위의 단원 순서 | 「중2-1 2학기 코스」 |
| **단원** | 코스 안의 한 묶음. 학생앱에서 「지금 단원 / 다음 단원」으로 보인다 | 「Ⅲ. 일차부등식」 |
| **단계** | 단원 안에서 순서대로 할 것 하나 = 카드 하나의 원본 | 📺 영상 → 📗 교재 쪽 → 📄 학습지 → 📝 백지테스트 |
| **카드** | 학생 한 명에게 배정된 단계 하나. 상태가 붙는다 | 「학생 B · 쎈 42~47쪽」 |
| **상태** | 배정됨 → 받음 → 하는 중 → 제출 → 확인 끝 | |

단계의 **종류** 일곱 가지: `vod` 📺 영상 · `book` 📗 교재 쪽 · `ws` 📄 학습지(시험지) · `blank` 📝 백지테스트 ·
`aha` 💡 아하노트 재풀이 · `rec` 🚑 보충(자동 카드 전용) · `etc` ✏️ 기타. 종류에 따라 「제출」이 자동으로 되는 것이 다르다(§4).

## 2. 서버에 새로 생기는 칸 (`lumen_store` 세 가지 키)

표를 새로 만들지 않는다. 키 세 종류만 더 쓴다. **누가 쓰는지가 키마다 하나뿐**이라 서로 덮어쓰지 않는다.

| 키 | 쓰는 쪽 | 읽는 쪽 | 내용 |
|---|---|---|---|
| `todo_courses` | 학원앱만 | 학원앱 | 코스 전부 `{courses:[{id,title,grade,units:[{id,title,steps:[{id,kind,title,ref,note}]}]}], upd}` |
| `todo_<학생코드>` | 학원앱만 | 학생앱·학원앱·레이스 엔진 | 그 학생의 카드 목록 `{items:[…], upd}` |
| `todo_st_<학생코드>` | 학생앱만 | 학원앱·레이스 엔진 | 학생이 누른 상태 `{ <카드id>: {st, at, photo, note} , upd}` |

카드 하나(`items[]`)의 모양:

```
{ id, kind, title, ref,            // ref: 쪽수·학습지id·영상id 등 (종류별)
  course, unit, unitTitle, order,  // 어느 코스·단원의 몇 번째
  due,                             // 마감(선택)
  src: 'course' | 'manual' | 'auto:ws' | 'auto:rec' | 'auto:aha' | 'auto:vod',
  tst: 'todo'|'got'|'doing'|'done'|'ok',   // 원장이 찍은 상태 (나눠 주기·확인 끝)
  tat: { got, doing, done, ok },           // 그 시각
  auto: { done, at }                       // 앱이 자동으로 알아낸 제출 (매쓰플랫 채점·영상 완주·재풀이 제출)
}
```

**보이는 상태 = 원장 상태 · 학생 상태 · 자동 제출 중 가장 앞선 것.** 순서는 `todo < got < doing < done < ok`.
`ok`(확인 끝)은 원장만 찍을 수 있다. 원장이 「받음」을 찍었는데 학생이 안 눌렀어도 받음이다(둘 다 → 앞선 쪽).

### 왜 세 키로 나누나
학생앱과 학원앱이 **같은 키에 동시에 쓰면** 한쪽 것이 지워진다(교재 자기채점 `hw_scores`에서 겪었다).
학생은 `todo_st_` 에만, 원장은 `todo_` 에만 쓰면 충돌이 없다. 서버 잠금 규칙도 그대로다 —
학생 코드가 붙은 키는 그 학생앱이 쓸 수 있고, 지우기는 원장 열쇠만 된다.

## 3. 카드는 어디서 오나

| 출처 | 언제 카드가 생기나 | `src` |
|---|---|---|
| **코스 배정** | 원장이 코스를 학생(반)에게 배정하면 **모든 단원의 단계**가 순서대로 카드가 된다 | `course` |
| 손으로 | 보드에서 「+ 카드 올리기」 — 한 명 또는 반 전체 | `manual` |
| 매쓰플랫 학습지 배정 | 수집기가 모은 배정 목록에 새 학습지가 있으면 「📄 받음 대기」 카드 | `auto:ws` |
| 리커버리 확정 | 확정 명단에 든 학생에게 「🚑 토요 보충」 카드 | `auto:rec` |
| 아하노트 힌트 발송 | 힌트를 보낸 질문마다 「💡 재풀이」 카드 | `auto:aha` |
| 강의실 배정 | 영상을 배정하면 「📺 영상 보기」 카드 | `auto:vod` |

자동 카드는 **학원앱이 보드를 열 때** 만든다(같은 출처·같은 id면 두 번 만들지 않는다).
학생앱은 만들지 않는다 — 학생앱은 `todo_<코드>` 를 읽기만 한다.

**이미 끝난 것은 카드로 만들지 않는다.** 처음 켤 때 실측으로 지난 7월 영상 배정까지 205장이 쏟아졌기 때문이다.
- 영상: 이미 완주했거나, 영상을 올린 지 45일이 넘었으면(마감이 남아 있지 않은 한) 만들지 않는다
- 학습지: 이미 채점된 것은 만들지 않는다 · 아하노트: 이미 해결된 질문은 만들지 않는다
- 이미 있는 카드는 그대로 두고 상태(자동 제출)만 올린다

리커버리 카드의 종류는 `rec` 🚑 (나눠 주기 대상이 아니다).

## 4. 「제출」이 자동으로 되는 것

| 종류 | 자동 제출 근거 | 학생이 누를 것 |
|---|---|---|
| 📗 교재 쪽 | 매쓰플랫 채점 기록(`mf_swb`)에 그 쪽이 채점됨 | 받음·하는 중만 |
| 📄 학습지 | 매쓰플랫 채점 기록에 그 학습지가 채점됨 | **받음**(시험지 받았는지) · 하는 중 |
| 📺 영상 | 시청 로그 완주(`vod_watch_logs.completed`) | 받음·하는 중은 안 눌러도 됨 |
| 💡 재풀이 | 아하노트 재풀이 사진 제출 | — |
| 📝 백지테스트 · ✏️ 기타 | 없음 | 받음 · 하는 중 · **제출(사진)** |

자동 제출도 학원앱이 보드를 열 때 알아내어 `auto.done` 에 적는다.
학생앱은 자기 화면에서 같은 근거(내 채점 기록·내 시청 로그)를 보고 **미리 ✅ 로 보여 줄 수 있다**(저장은 안 함).

## 5. 화면

### 5-1. 학원앱 PC — 「🗂 할 일 보드」 새 탭 (`오늘의 확인` 그룹, 숙제체크 다음)

나눠 주기는 매일 하는 일이라 `오늘의 확인` 그룹에 둔다.

네 갈래(칩):
1. **보드** — 반 칩 → 다섯 열(배정됨·받음·하는 중·제출·확인 끝). 단원 거르개. 카드를 누르면 상태 바꾸기·삭제·마감.
   원장 카드는 노란 띠, 자동 카드는 보라 띠. 「+ 카드 올리기」(한 명/반 전체), 「✔ 전부 확인 끝」.
2. **코스 짜기** — 코스 목록 → 코스 하나: 단원 추가·이름·순서(▲▼), 단원마다 단계 추가(종류 칩 + 제목 + 참고).
   단계 종류가 📺 이면 강의실 영상을, 📄 이면 매쓰플랫 학습지 제목을 고를 수 있다(선택).
   「👥 배정」 → 학생 체크(반 단위 전체 선택) → 그 학생들에게 카드 생성. 이미 배정된 학생은 표시.
3. **나눠 주기** — 오늘 수업 반 → 학습지/백지테스트 카드 하나 고르기 → 이름 격자 톡톡 → 「받음」(원장 상태).
   「전원 받음」·「안 받은 학생만」. 태블릿 손가락 크기(44px 이상).
4. **학생별** — 학생 하나의 카드 목록을 순서대로. ▲▼ 순서, 단원 접기, 지난 것.

홈 「오늘의 확인」에 한 줄: **「📄 학습지 아직 못 받음 n명」**(배정됐는데 하루 지나도 받음이 없는 학습지 카드).

### 5-2. 학원앱 폰 — 아래탭 「📋 할 일」
- 반 칩 → 학생 카드(진행 n/m, 지금 단원) → 학생 누르면 카드 목록(상태 단추)
- 「나눠 주기」 — 같은 이름 격자

### 5-3. 학생앱 (v2-97)
- 홈 「📌 오늘 할 일」 아래에 **「📋 이번 단원」** 목록: 순서 번호 · 제목 · 상태 단추 3개(받음 / 하는 중 / 제출).
  자동 제출 종류는 단추 대신 「매쓰플랫에서 채점하면 자동 ✅」 안내. 제출이 사진인 종류는 사진 고르기 → 업로드.
  이번 단원이 다 끝나면 다음 단원이 자동으로 올라온다.
- 새 화면 **「📋 내 할 일」** (홈 목록 머리 → 이동): 지금 단원 / 다음 단원들(잠긴 모양, 제목만) / 끝낸 것.
  「내가 무엇을 할지」가 한눈에.
- 기능 스위치 `stu_features.todo` 로 학년별 끄기 가능(다른 기능과 같은 방식).

## 6. 진도 레이스 점수 (§ 받음1 · 하는 중2 · 완료3)

`sync/race_engine.js` 가 `todo_*`·`todo_st_*` 를 읽어 카드마다 **받음 1점 · 하는 중 2점 · 제출/확인 3점**(누적 아님,
가장 앞선 상태 하나)을 시즌 점수에 더한다. 시즌 설정 `race_season.todoPts` 가 `false` 면 더하지 않는다(기본 켬).
학원앱 순위표 계산기(`raceCompute`)도 **같은 규칙**이어야 한다 — 한쪽만 고치면 두 화면 점수가 어긋난다.

## 7. 손대지 않는 것
- 진도 레이스·리그·리커버리·강의실·아하노트·매쓰플랫 화면과 저장 방식 (읽기만 한다)
- 서버 표 구조 (새 표 없음, `lumen_store` 키 세 종류만)
- `student_v1.html`·`parent.html` (원장 지시 없이는 절대)
- **시험지 규칙** — 학습지 문제 그림은 어디에도 띄우지 않는다. 카드에는 제목만.
