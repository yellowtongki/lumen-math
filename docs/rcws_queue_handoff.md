## 2. 서버 쪽에 넣은 것 (이 세션에서 끝냄)

### `sync/rcws_make.js` — 세 군데 고침

| 고친 것 | 내용 |
|---|---|
| **토큰 버그** ⚠ | **매쓰플랫 토큰이 5분 만에 끊긴다.** `mf()` 에 401 재로그인이 없어 5분 넘는 작업은 전부 `UNAUTHORIZED` 로 죽었다(첫 실행에서 3명 만들고 13명이 이렇게 죽음). → 2분 30초마다 미리 로그인 + 401이면 한 번 더 받아 재시도 |
| **쌍둥이 캐시** | 같은 문항은 이번 실행 안에서 한 번만 + Supabase `mf_derivation_cache` 조회. 표가 없으면 조용히 끄고 매쓰플랫만 쓴다 |
| **간격** | `--gap`(기본 3000ms). 캐시에서 꺼낸 것은 안 쉰다. 보안문자가 뜨면 **그 자리에서 전부 멈춤 — 재시도하지 않는다** |
| **예약 모드** | `--req [키]` (기본 `ws_make_req`) |

> ⚠ **토큰 버그는 리커버리만의 문제가 아니다.** 매쓰플랫을 5분 넘게 쓰는 다른 스크립트도
> 같은 길로 죽는다. `sync/mypaper_to_mathflat.js` 는 이미 401 재로그인이 있으니 그쪽을 본뜨면 된다.

### `sync/mf_derivation_warm.js` — 새벽 일꾼 (새로 만듦)

최근 35일 오답 문항(학습지 `problem_id` + 교재 `workbook_problem_id` → `mf_textbook_<교재>` 의 `pimg`)
중 캐시에 없는 것만, 유형별 필터를 만들어 3초 간격으로 받아 쌓는다.
한 번에 300개까지, 보안문자가 뜨면 멈추고 다음 새벽으로 넘긴다. 90일 넘은 줄은 지운다.

### 워크플로

| 파일 | 언제 | 무엇 |
|---|---|---|
| `.github/workflows/mathflat-ondemand.yml` | **5분마다** (이미 있던 것) | 맨 끝에 「리커버리 학습지 예약 처리」 단계 추가 — `node sync/rcws_make.js --req --gap 3000` |
| `.github/workflows/mathflat-derivation-warm.yml` | **매일 05:10 KST** (새로 만듦) | `node sync/mf_derivation_warm.js` |

둘 다 `concurrency: mathflat-ondemand` 한 줄에 묶었다.
**보안문자는 계정 단위 속도 제한이라, 정기 수집과 동시에 돌면 합산되어 걸린다.**

### 캐시를 두는 곳 — 표가 없어도 된다

전용 표 `mf_derivation_cache` 가 있으면 거기, **없으면 `lumen_store` 의 `mfd_<번호>` 키**에 담는다. 코드가 알아서 고른다.

전용 표를 만드는 SQL(`docs/mf_derivation_cache.sql`)은 **서비스 열쇠로 돌릴 수 없다**(PostgREST 는 DDL 을 못 하고 `exec_sql` RPC 도 없다). 원장님이 Supabase 화면에서 한 번 돌리면 그때부터 저절로 표 쪽을 쓴다. **안 돌려도 전부 정상 작동한다.**

유사 문제는 앞 30개만 담는다 — `pick()` 은 보통 2개만 집으므로 넉넉하고 저장소가 작아진다.

실측(11/6 밤): 같은 학생을 두 번 돌렸더니 두 번째는 **매쓰플랫 호출 0회**, 6개 전부 캐시에서 나왔다. 최근 7일 오답만 1,147문항 — 매일 새벽 500개씩이면 일주일이면 거의 다 찬다.

## 3. 남은 일 — 학원앱 (그쪽 세션)

지금 학원앱은 **원장 PC 브라우저에서 매쓰플랫에 직접 로그인해 즉시 만든다**
(`sync/appbuild/modules/rcws_teacher.js` v19-92·93, 2026-10-09 원장 「즉시」 요청).
이 길이 11/6에 보안문자로 막혔다. **예약 방식으로 바꾸면 된다.**

### 바꿀 것

1. **「⚡ 확정 전원 학습지 생성」 버튼** → 매쓰플랫 직접 호출 대신 `lumen_store` 에 요청만 쓴다

   ```js
   // ws_make_req
   { status: 'requested', wk: '2026-11-07', reqAt: <ISO>, by: 'app' }
   ```

   쓰고 나면 바로 「예약했습니다 · 5분 안에 시작합니다」를 보여 주고 끝낸다.

2. **진행률 띠** — 같은 키를 몇십 초마다 읽어 보여 준다. 서버가 이렇게 적는다.

   ```js
   { status: 'running'|'done'|'stopped',
     wk, total: 16, done: 7,
     items: [{ key, name:'한○○', ok:true, wsId:85499807, n:19, why:null }, …],
     startedAt, finishedAt, note,      // note = 멈춘 이유(보안문자 등)
     madeN, totalProblems, updated }
   ```

   - `running` → 「7/16 만드는 중 · 약 14분 남음」 (남은 시간 ≈ (total−done) × 2분, 캐시가 차면 훨씬 빠름)
   - `done` → 「16명 완료 · 1,173문항」
   - `stopped` → `note` 를 그대로 보여 준다 (「매쓰플랫 보안 확인 후 다시 눌러 주세요」)

3. **🔐 매쓰플랫 계정 칸(v19-180)은 그대로 두되, 안 써도 된다고 알려 주기.**
   서버에 이미 `MATHFLAT_ID`·`MATHFLAT_PASSWORD` 가 있다. 예약 방식에서는
   **원장 PC 에 비밀번호를 두지 않아도 된다** (`or_mf_id`/`or_mf_pw` 불필요).
   직접 생성 길을 비상용으로 남긴다면 칸도 남긴다.

4. **끝났을 때 푸시 알림** — `VAPID_PRIVATE_KEY` 가 이미 워크플로에 있다. 원하면 서버에서 보낸다.

### 안 바꿔도 되는 것

- 설계 규칙(쌍둥이 2 · 교과서 1 · 교재 오답 쌍둥이 1 · 보강)은 **그대로**다
- `rc_ws_made` · `rc_state` 기록 모양도 **그대로**다. 보드는 손댈 것이 없다
