# 📚 교재·교과서 손풀이 — 구현 계약 (1단계)

> 2026-09-14 · 원장 승인: 시안 3판 「추천대로 진행」
> 목표: 학생이 **손풀이 → 교재 → 쪽 → 번호**를 눌러 선생님 풀이를 본다.

> 모양은 이정민(명작수학) 학생 화면: **영상이 맨 위, 아래에 방법별 풀이 여러 장**.

「문제 / 스스로 확인하기」) **순서대로** 다른 사각형이 된다.

## 1. 저장 (lumen_store)

### 1-1. `book_pdfs` — 교재별 PDF 등록부
```js
{ byBook: { "<bid>": {
    bid:"3227375", title:"교과서_비상교육 - 미적분1",
    path:"book/1789399393819_1_ydexrq.pdf",   // school_pdfs 버킷 안 경로
    url:"https://…/school_pdfs/book/….pdf",   // 공개 URL
    pdfPages:188,
    offset:0,            // 인쇄쪽 = PDF쪽 + offset
    at:"ISO", by:"teacher"
} }, updated:"ISO" }
```

### 1-2. `book_boxes_<bid>` — 쪽별 문항 사각형
```js
{ bid, pages: {
   "<인쇄쪽>": {
     wpid:"53556882",        // 매쓰플랫 workbook_page_id
     cols:2,                 // 1 또는 2 (열 수)
     boxes:[ { n:"1",                    // 기본 번호(문자열)
               x:0.06,y:0.52,w:0.42,h:0.16,   // ← 0~1 비율, 쪽 그림 기준
               ids:[225991771,225991772],     // 매쓰플랫 wpId 목록
               ok:true } ],                   // false = 「확인 필요」(노란 점선)
     auto:"pair"|"even"|"hand",   // 어떻게 만들어졌나
     at:"ISO"
   } }, updated:"ISO" }
```
좌표는 **반드시 비율(0~1)** 로 저장한다. 렌더 배율이 기기마다 다르다.

### 1-3. `hand_solutions` — 기존 저장소에 출처 `book` 추가
기존 ITEM에 아래 항목을 더한다. 기존 `mf`/`exam`/`etc` 항목은 건드리지 않는다.
```js
ITEM = { id:"h_<ts>_<n>",
   src:'book',
   srcKey:"book|<bid>|<인쇄쪽>|<번호>",   // 같은 문항의 풀이는 srcKey가 같다
   bid, page:40, num:"1", ids:[225991771,225991772],
   img:"https://…/aha_photos/hand/book/<bid>/<page>_<num>_<ts>.jpg",
   title:"분모의 최고차항으로 나누기",   // 방법 제목(없으면 '')
   ord:0,                                // 같은 문항 안 순서 0,1,2…
   vid:{ yt:"영상ID", start:111 } | null, // 유튜브 + 시작 초
   date:"YYYY-MM-DD", by:"teacher" }
```
**교재 풀이는 학생 배정(codes)이 없다.** 교재에 붙고, 그 교재를 등록한 학생이면 누구나 본다.

### 1-4. `book_cfg_<bid>` — 교재별 공개 규칙
```js
{ reveal:'open'|'scored'|'hint', hidden:false, updated:"ISO" }
```
- `open` (**기본**) — 등록 학생 누구나 번호를 누르면 본다 (이정민식)
- `scored` — 그 문항을 채점(O/X)한 학생만
- `hint` — 틀린 학생이 힌트 3단계를 보거나 재풀이를 올린 뒤
- `hidden:true` — 학생앱에서 이 교재를 숨김

## 2. 사각형 자동 배치 (브라우저에서)

이 교과서는 **스캔본**이라 글자층에서 번호 좌표를 읽을 수 없다. 대신 **번호 글자의 생김새**를 쓴다.
교과서의 문제 번호는 예외 없이 **「회색 숫자 + 색깔 숫자」 두 글자**다 (`01` `02` … `15`).
회색은 `rgb(155,156,159)`, 색깔은 단원마다 다르다(중단원 녹색 `rgb(9,119,59)`, 대단원 진한 갈색 등).

### 알고리즘 (실측 43% 정확 일치 — 나머지는 균등 분할 + 원장 끌기)
1. pdf.js로 쪽을 캔버스에 그린다 (가로 1000px 기준).
2. **회색 마스크**: `|r-g|<14 && |g-b|<14 && 128<=r<=190`
3. **색깔 마스크**: `max(r,g,b)-min(r,g,b) >= 40 && max <= 225`
4. 두 마스크에서 각각 덩어리(연결 요소)를 찾는다. 높이 `0.012H~0.022H`, 너비 `0.004W~0.025W`만 남긴다.
5. 회색 덩어리 오른쪽에 (`gx1-3 ≤ cx0 ≤ gx1+9`, 세로 겹침 55% 이상, 높이 차 9px 이내)
   색깔 덩어리가 붙어 있으면 **번호 닻**으로 본다.
6. 닻을 x로 두 무리(왼쪽/오른쪽 열)로 나누고 각 열에서 y 순으로 세운다.
7. **닻 개수 == 매쓰플랫 그 쪽 문제 개수** 이면 → 닻마다 상자를 만든다(`ok:true`, `auto:'pair'`).
   - 상자 = `x0 = 닻.x - 0.004`, `y0 = 닻.y - 0.006`, `y1 = 다음 닻.y - 0.006`(없으면 0.93),
     `x1 = 2열이면 0.47(왼쪽)/0.95(오른쪽), 1열이면 0.95`
8. 개수가 다르면 → **균등 분할**(`ok:false`, `auto:'even'`): 본문 영역(y 0.06~0.93)을 문제 수로 나눈다.
   노란 점선으로 그려 「확인 필요」를 보여 준다.
9. 원장이 상자를 끌거나 크기를 바꾸면 `ok:true`, `auto:'hand'`.

**열 수 판정**: 닻이 두 x무리로 갈리면 2열. 아니면 1열. 원장이 「1열/2열」 단추로 바꿀 수 있다.

### 실측 (2026-09-14, 비상 미적분1 188쪽 · 매쓰플랫 126쪽)
| 대상 | 자동으로 개수까지 맞은 쪽 |
|---|---|
| 매쓰플랫 쪽 전체 126 | **60쪽 (48%)** |
| 연습문제·중단원 점검처럼 문제 3개 이상인 쪽 53 | 25쪽 |
| 시험한 5쪽 (p.25·26·40·41·55) | **5/5** |

브라우저(pdf.js + 캔버스)에서 같은 알고리즘을 돌려 p.25 3개 · p.26 6개 · p.40 4개 · p.41 5개 ·
p.55 1개를 매쓰플랫 문항 수와 똑같이 찾았다. 스캔본이라 **글자층이 없어** 좌표를 글자에서
읽을 수 없고 색·모양만으로 찾는 것이라 이 정도가 한계다.

**중요**: 126쪽을 미리 다 손볼 필요가 없다. **풀이를 넣는 쪽만 그때 확인**하면 된다
(수업 한 번에 보통 1~5쪽). 나머지는 그대로 두었다가 나중에 손대면 된다.

## 3. 학원앱 (lumen_v18-175.html)

손풀이 화면 탭에 **`['book','📚','교재','']`** 을 맨 앞에 추가한다.
전역 상태 이름은 **`BKH`** 를 쓴다 (학생앱 `BK`와 겹치지 않게).

### 3-1. 교재 목록 (`BKH.view='list'`)
- `mf_swb_<학생코드>` 전부를 합쳐 교재별 **등록 학생 수**를 센다.
- `mf_bookans_<bid>` 로 **쪽 수 · 문항 수**.
- `hand_solutions` 에서 `src==='book'` 인 항목으로 **풀이 있는 쪽 수 · 풀이 수**.
- `book_pdfs` 로 **PDF 등록 여부** 배지.
- 각 줄: 교재명 · 등록 학생 n · 문항 n · 풀이 있는 쪽 n/전체 · [📄 PDF 올리기 | 열기]
- 정렬: PDF 있는 것 먼저, 그다음 등록 학생 많은 순.

### 3-2. PDF 등록
- 파일 고르기 → `school_pdfs` 버킷 `book/<ts>_<슬러그>.pdf` 로 업로드 (`storageSlug` 재사용)
- pdf.js로 총 쪽수를 읽는다.
- **쪽 맞춤**: 「PDF 몇 쪽이 인쇄 p.몇 쪽인가」를 숫자 두 칸으로 받아 `offset`을 계산.
  기본값은 `offset=0`(대부분 맞다). 미리보기로 확인시킨다.
- 45MB 넘으면 막지 말고 그대로 올린다(원장 PDF는 48MB). Storage 상한만 지킨다.

### 3-3. 쪽 목록 (`BKH.view='pages'`)
- `mf_bookans_<bid>` + `mf_swb_*` 의 wpid→쪽 사전으로 쪽 목록을 만든다.
- 줄마다: `p.40` · 문항 8 · 풀이 3/4 · 🔥(최근 7일 오답 많은 쪽)
- 오답 수는 `mf_answer_records` 를 `book_id=eq.<bid>` + 최근 7일로 조회해 쪽별로 센다.

### 3-4. 쪽 작업대 (`BKH.view='page'`) — 3분할
왼쪽(쪽 목록) | 가운데(교과서 쪽 + 사각형) | 오른쪽(필기 조각)

**가운데**
- pdf.js로 해당 PDF 쪽을 캔버스에 렌더.
- 사각형을 겹쳐 그린다. 색: 풀이 있음 초록 / 비어 있음 파랑 / 확인 필요 노란 점선 / 고른 것 굵게.
- 상자 끌기(이동)·모서리 끌기(크기)·번호 바꾸기·상자 추가/삭제.
- [🔄 자동 배치 다시] [1열/2열] [💾 저장] 단추.

**오른쪽**
- 「✍️ 필기 올리기」 — 사진(JPG/PNG) 또는 PDF 한 장.
- 올린 그림 위에서 **영역을 끌어** 조각을 만든다.
- 조각을 만들면 가운데에서 번호를 고르라고 하고, 고르면
  → 캔버스로 잘라 JPEG(긴 변 1600px, 품질 0.82)로 만들어
  → `aha_photos` 버킷 `hand/book/<bid>/<page>_<num>_<ts>.jpg` 업로드
  → `hand_solutions` 에 ITEM 추가 → 저장.
- 같은 번호에 또 붙이면 `ord`가 1씩 는다. 방법 제목을 물어본다(비워도 됨).
- 붙인 조각 목록(작은 그림 + 제목 + 삭제 + 🎬 영상 링크 넣기).

**🎬 영상**: 「유튜브 주소 + 시작 시각(1:51 또는 111)」 한 줄 입력 → `vid` 저장.

### 3-5. 교재 설정
- 공개 규칙 3개 라디오(기본 `open`) + 「학생앱에서 숨김」 스위치 → `book_cfg_<bid>`.

## 4. 학생앱 (student_v2-80.html)

손풀이(`HS`) 화면 탭에 **「📚 교재·교과서」** 추가. 상태 이름은 **`HSB`**.

### 4-1. 교재 목록
- 내 `mf_swb_<내코드>` 의 교재 중, `hand_solutions` 에 `src==='book'` 풀이가 있는 교재만 보인다
  (`book_cfg_<bid>.hidden` 이면 숨김).
- 줄마다: 교재명 · 풀이 있는 쪽 n · 내 오답 n · 풀이 있는 내 오답 n · 최근 쪽.
- 맨 아래 큰 단추 **「🔴 내 오답 풀이만 모아 보기 (n)」**.

### 4-2. 쪽·번호 판
- 왼쪽 세로: 쪽 목록(풀이 있는 쪽만, 내 오답 있으면 빨간 점).
- 오른쪽 격자: 그 쪽의 번호 단추 — 매쓰플랫 번호 그대로(`5.(2)`는 `5` 하나로 묶어 보인다).
  - 내가 틀린 번호 → 빨강 · 풀이 없는 번호 → 연하게(누를 수 없음) · 보는 중 → 남색
- 범례 한 줄.

### 4-3. 풀이 한 장 (이정민식)
위에서 아래로:
1. **🎬 영상** — `vid`가 있으면 유튜브 embed `?start=<초>`. 없으면 이 칸 자체를 안 그린다.
2. **방법별 풀이** — `ord` 순서로, 제목이 있으면 `1 분모로 나누기` 처럼 빨간 소제목 + 그림.
   그림을 누르면 크게 보기(`openAhaPhoto` 재사용).
3. 「이미지를 누르면 크게 볼 수 있어요」 안내.
4. 내 결과 배지(✗ 틀림 / O) + 유형.
5. 단추: [다음 틀린 문제 → n번] [🙋 이 문제로 IB아하노트] [🔁 다시 풀어 올리기]

**공개 규칙**: `book_cfg_<bid>.reveal` 이
- `open` → 그냥 보인다 (기본)
- `scored` → 그 문항을 채점한 기록이 있어야 보인다. 없으면 자물쇠 + 「채점하면 열려요」
- `hint` → 틀린 문항은 힌트 3단계/재풀이 뒤. 맞은 문항은 바로.

### 4-4. 내 오답 풀이만 모아 보기
- 내가 틀린 문항 중 풀이가 있는 것을 쪽 순서로 카드 목록 → 누르면 4-3 화면.

**내 오답 자료**: `mf_answer_records` 를 `mf_student_id` + `book_id` 로 조회
(학생앱에 이미 쓰는 방식이 있다 — 8346·9139줄 근처 참고). `workbook_problem_id` 로 맞춘다.

## 5. 지켜야 할 것

- 두 앱 모두 **단일 HTML** 구조 유지. 중첩 템플릿 리터럴 금지(문자열 결합만).
- 버전 올리기: 학원앱 `APP_VER`(289줄 근처), 학생앱 `STU_VER`(3354줄 근처) + 버전 메모 추가.
- 기존 버전 파일 수정 금지. **새 파일**(`lumen_v18-175.html`, `student_v2-80.html`)로 만든다.
- 커밋·push·배포는 하지 않는다 (지시자가 한다).
- 학생 개인정보·비밀번호를 코드에 넣지 않는다.
- 교재 PDF 원본은 학생앱에 통째로 내려보내지 않는다. **문항 사각형으로 자른 조각만** 나간다.
- 저장은 전부 `lumen_store` upsert. 실패하면 사용자에게 알린다(조용히 삼키지 않는다).
