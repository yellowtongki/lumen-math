## 1. 흐름 — 여섯 단계

```

② 문항 나누기     매쓰플랫 AI 문항 인식(기출 쌍둥이 파이프라인 ④⑤와 같은 서버) → 문항 상자 그림·유형·난이도·문제은행 원본
                  (매쓰플랫이 못 자르면 Claude 비전으로 자르고, 원장님이 「문항 경계 손보기」로 고친다)
③ 우리 자료 모으기 자동: 그 반에 배정된 매쓰플랫 학습지 문항 + 교재 은행(학생이 푼 쪽) + 기출 쌍둥이 학습지

                  → 원장님 ✓/✗ 확정 (확정 전엔 «후보», 적중률엔 확정만)
⑤ 결과 화면·보고서 적중률 도넛(고른 기준) · 출처 비중 · 난이도·킬러 · 반복 출제 · 문항 카드
                  🖨 학부모 보고서(검정+붉은 강조) · 학생별 「적중 문항을 우리 자료에서 풀 때 맞혔나」
⑥ 블로그 자료     📝 .md 내보내기 (이름·문제 원문·그림 없음, 「수학비서」 단어 없음)
```

## 3. 저장 — lumen_store 키

```js
exam_hit_req            // 앱 → 워커 요청 { status:'requested'|'running'|'done'|'error', examId, step, reqAt, by:'app' }
exam_hit_<examId>       // examId = 옥길중_중1_2026_2_중간 처럼
{
  exam:  { school, grade, year, semester, term, date, uploadedAt, pages:[storage path…] },
  basis: 'same' | 'same+var' | 'type',            // 원장님이 고른 적중 기준 (기본 'same+var')
  items: [{ no, img, type:{cid, name, chapter}, level, killer, answerType, source:'textbook'|'ours'|'outside'|'',
            repeat:[{year, no}],                   // 같은 학교 지난 기출의 같은 세부유형
            cands:[{ matId, kind:'same'|'var'|'type'|'text', score, why }],  // 자동 후보
            hit:  { kind, matId, ok:true|false|null, by:'teacher', at } }],  // ok=null 이면 미확정
  mats:  [{ matId, kind:'ws'|'book'|'twin'|'upload', title, where:'학습지 이름 3번' | '교재 87쪽 5번', img, problemId, cid }],
  stats: { total, hitSame, hitVar, hitType, textOnly, byBasis:{same, 'same+var', type}, killers, levelAvg, sourceMix },
  confirmedAt
}
exam_hit_index          // { items:[{ examId, school, grade, year, semester, term, hitPct, confirmedAt }] }
```

- `mats.img`·`items.img`는 Storage `exam_images`(비공개) 경로. 화면·인쇄는 서명 주소(2시간)로 연다 — 기출 분석과 같은 방식.
- 학생별 결과는 저장하지 않고 화면에서 그때그때 `mf_answer_records`로 계산한다 (적중 문항에 짝지어진 우리 자료 문항을 그 학생이 맞혔는지).

## 4. 적중 판정 규칙

| 등급 | 뜻 | 자동 근거 |
|---|---|---|
| **같은 문제** | 숫자·조건까지 같다 | 문제은행 `problemId` 동일 → 확실. 아니면 Claude 비전이 두 그림을 보고 「동일」 |
| **변형** | 묻는 것·풀이 같고 숫자·조건만 다르다 | 매쓰플랫 유사 필터가 쌍둥이로 돌려줌, 또는 Claude 「숫자만 다름」 |
| **유형** | 같은 유형 번호(cid) | 유형 번호 일치. 기준 ③에서만 적중 |
| **지문만 겹침** | 소재·그림만 같고 묻는 것이 다르다 | Claude 「소재만 같음」. **적중 아님**, 따로 센다 |

- 후보는 **같은 중단원 자료만** 추려 비교한다 (수천 문항 전부 비교하지 않음 → 비용·시간 절약).
- Claude 비전 판정은 문항마다 한 번, 후보 그림 최대 6개를 함께 보여주고 JSON으로 받는다. 시험지 한 장(24문항) ≈ 24회 호출, 수백 원 수준.
- **확정은 원장님만.** 후보 줄마다 ✓ 적중 / ✗ 아님 / 등급 바꾸기. 미확정이 남아 있으면 보고서에 「후보 N건 미확정」이라고 적는다.

## 7-1. 실제 구현 (2026-10-04, v19-74)

- **올리기 자리**: 학원앱은 비공개 `exam_images` 에 직접 쓸 수 없다(서버 잠금). 그래서 학원앱이 쓸 수 있는 `aha_photos/_exam_hit/<무작위 16자>/` 에
  잠깐 올리고, 워커가 받자마자 `exam_images/hit/<시험 해시>/src/` 로 옮긴 뒤 임시 파일을 지운다. 서버 구조(SQL)는 바꾸지 않았다.
- **워커 자리**: 새 워크플로를 만들지 않고 `mathflat-ondemand.yml`(5분마다)에 단계 하나를 더했다. 같은 동시 로그인 방지 그룹이라 정기 수집과 매쓰플랫 로그인이 겹치지 않는다.
  요청이 없으면 몇 초 만에 끝난다. `pdf-lib` 는 요청이 있을 때만 즉석 설치.
- **우리 자료** = `mf_answer_records` 에서 그 학교·학년 재원생의 «학기 시작(1학기 1/1, 2학기 7/1) ~ 시험 첫날» 기록. 문항 단위로 묶고(학습지 `problem_id`, 교재 `workbook_problem_id`)
  학생별 가장 최근 정오를 `mats[k].res` 에 둔다(학생 코드만, 이름 없음). 그 시험 자체의 원본·쌍둥이 학습지는 뺀다.
- **후보 고르기**: 매쓰플랫이 찾은 «가장 닮은 원본» 번호와 우리 자료 문제 번호가 같은 것(문제 그림 주소 안의 번호로 비교) → 같은 유형 번호 순, 최대 6개. 같은 그림은 하나로 묶고 나머지는 `also`.
- **판정 모델**: `claude-sonnet-5-5` (안 되면 `claude-sonnet-4-6`). 문항당 한 번, 온도 0.
- **반복 출제**: `ms_exam_bridge` 의 지난 같은 시험 유형 번호, 교육과정이 바뀐 해(2024 중1 등)는 유형 이름으로.
- **킬러**: 매쓰플랫 난도 4·5 (기출 DB 시험지는 난이도 6 이상).
- **시범**: `exam_hit_옥길중_중1_2025_2_중간_시범` — 2026 2학기 중간 시험지가 아직 서버에 없어, 2025 같은 시험을 2026-07-01~10-01 자료와 대조.
  워커 `--mydb 387569 --exam-id …_시범 --from 2026-07-01 --to 2026-10-01`.

- **시범 결과(2026-10-04)**: 23상자 인식(실제 21문항 — 서술형이 둘로 잘린 것은 「앞 문항과 합치기」로) · 학생 7명 기록 24,460건 → 서로 다른 문항 10,877개.
  판정 3회 다듬음: 1회차 변형 16(너무 너그러움) → 「도형·질문이 다르면 변형 아님」 → 「숫자·점 이름 하나라도 다르면 같은 문제 아님」.
  최종 같은 문제 2 · 변형 11 · 유형 10 → 같은 문제 + 변형 13/23(57%). 눈으로 확인한 것 중 17번 «같은 문제»는 실제로 숫자가 다른 변형 — 원장 확정이 꼭 필요하다.

## 8. 주의

- 매쓰플랫 인식·유사 필터는 로그인이 필요해 **워커(GitHub 서버)**에서 돈다. 동시 로그인이면 원장님 접속이 끊길 수 있으니 `mathflat-collect` 그룹으로 묶어 정기 수집과 겹치지 않게 하고, 올리기 뒤 5~10분 기다리는 화면을 둔다.
- AI 판정 열쇠는 서버 비밀(ANTHROPIC_API_KEY). 학원앱에는 열쇠를 두지 않는다.
- 시험지 그림은 `exam_images` 비공개 버킷에만. 저장소·로그에 시험 문항·학생 이름을 남기지 않는다.
- 자료 수천 문항을 매번 전부 비교하지 않는다 — 같은 중단원만.

## 9. 2026-10-05 추가 — 기출 DB에서 찾기 · 카드뉴스 (학원앱 v19-80)

### 9-1. 📚 기출 DB에서 찾기
원장 요청: 「시험지 올리기와 수학비서에 내가 구매한 db가 있으니 거기서 기출을 찾아서 확인하는 기능도 추가하자」.
- **목록 색인** `lumen_store.ms_mydb_index` = `{ updated, items:[{ id, t(제목), f(폴더), sc(제목의 학교), y, g, sem, term, n(문항 수), ok(DB화 완료) }] }` (약 200KB · 1,515장 · 29개 학교).

### 10-2. 요청 — `exam_hit_req.src`
```js
src: { tb:{ on:true, mode:'all'|'scope', bids:['3219971', …] },   // 교과서 — 체크한 지정 교과서
       ms:['711431', …],                                         // 수학비서 학습지 id
       lib:['L…', …],                                            // 자료함 id
       mf:true }                                                 // 매쓰플랫 채점 기록
```
- `src` 가 없으면 예전과 같다 + **고등부만** 지정 교과서 전체(`mode:'all'`)를 기본으로 넣는다. `tb.bids` 가 비면 `mf_textbooks.bySchoolGrade['학교|학년']` 의 SCHOOL 책 전부.
- `mode:'scope'` = 시험 문항의 유형(cid)이 나오는 쪽의 소단원 제목 + 시험 문항 중단원 이름과 같은 쪽 제목 → 그 소단원 쪽만. 맞는 쪽이 없으면 전체.
- 같은 문항이 매쓰플랫 교재 기록(`wb:<id>`)에도 있으면 정오가 있는 기록 쪽을 남기고 교과서 쪽은 뺀다.
- 분석하는 시험지 자체(`req.mydb`)가 ms 에 있으면 뺀다. 결과 `exam_hit_<시험>.src` 에 요청한 src 를 남겨 「🔄 다시 판정」이 같은 구성으로 돈다.

### 10-3. 저장 키
| 키 | 모양 | 쓰는 쪽 |
|---|---|---|
| `ms_paper_<id>` | `{ id, title, folder, grade, uploadedAt, n, status:'ready'\|'pending'\|'error', err, updated, items:[{ no, img, cid, level, src, srcWb, pid }] }` — `img` = exam_images `ms/<id>/<번호>.png` | 워커 |
| `ms_papers_index` | `{ updated, items:[{ id, title, folder, sub?, grade, uploadedAt, n, status, exam }] }` — 학년 폴더 전부(기출은 `exam:true`) + 다른 폴더의 1년 안 학습지. 학년 폴더 아래 폴더는 `folder`=학년 폴더, `sub`=아래 폴더 (약 160KB) | 워커 → 앱 |
| `exam_lib` | `{ updated, items:[{ id, title, school, grade, sem, year, uploadedAt, src, path, n, status, err, items:[…], moved, deleted }] }` — 앱이 `status:'pending'`·`src:'aha_photos/_exam_hit/lib_<id>/1.pdf'` 로 넣고, 워커가 `exam_images/lib/<id>.pdf` 로 옮겨 인식(`lib/<id>/<번호>.png`). 앱에서 지우면 `deleted:true` 만(워커는 건너뜀). 둘 다 쓰므로 쓰기 직전에 다시 읽어 그 항목만 바꾼다 | 앱 + 워커 |
| `exam_hit_src_<학교>_<학년>` | `{ folders:[…], tbMode, tbOff:{bid:1}, msOff:{id:1}, msOn:{id:1}, libOn:[…], mf, updated }` — 앱만 쓴다. 워커는 `req.src` 만 읽는다(새벽 준비가 msOn 을 미리 인식하는 것만 예외) | 앱 |

- 결과 `exam_hit_<시험>.mats[k].kind` = `textbook` · `ms` · `upload`(자료함이면 `lib:true`) · `ws` · `book`. 키 이름: `tb:<문항id>` · `ms:<학습지id>:<번호>` · `lib:<자료id>:<번호>` · `up:…` · `ws:…` · `wb:…`.
- `stats.byKind = { textbook:{mats, hit}, ms:{…}, upload:{…}, ws:{…}, book:{…} }` — `mats` = 대조한 자료 문항 수(워커), `hit` = 자동 1순위 후보가 그 종류인 기준 안 적중 수(워커, 확정 전). **화면의 «우리 자료별 적중» 숫자는 학원앱이 원장님 ✓/✗ 를 반영해 다시 센다**(`htEff` 와 같은 방식, 한 문항은 맨 앞 적중 자료 하나로). `mats` 는 워커 값을 그대로 쓴다.
- 판정 규칙은 그대로: 원본 번호 같음(문제은행 `p`·교재 `b`) → 후보 맨 앞, 같은 유형 번호 → 후보, 그림 판정. 수학비서·자료함 문항은 매쓰플랫 인식의 `src`(가장 닮은 원본)를 `pid`/`wbp` 로 써서 같은 길을 탄다. 교과서 은행 문항은 `wbp`=은행 문항 id, `pid`=그림 주소의 문제 번호.
- 학생별 「시험 전에 맞혔나」는 매쓰플랫 자료(`ws`·`book`)만. 교과서·수학비서·프린트로 적중한 문항은 «나눠 줌».
- 학부모 보고서·블로그 .md 의 자료 이름은 종류만: 교과서 · 학원 학습지 · 학원 프린트 · 매쓰플랫 학습지·교재 (「수학비서」 낱말은 밖으로 안 나간다, §6).
