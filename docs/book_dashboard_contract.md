# 📗 교재 상황판 — 계약서

원장 결정 2026-09-19: **시안(https://claude.ai/artifact/QfYtW8v8HsAHi2pmiGXoDd) 그대로 진행**.
학원앱 **v19-23** 한 버전에 담는다.

## 0. 왜 만드는가

매쓰플랫 자동 수집으로 **교재 채점 기록 5만여 건**(`mf_answer_records`, `source='교재'`)이
이미 쌓여 있는데, 학원앱에서는 **학생 한 명씩** 밖에 볼 수 없었다.
「어느 교재에서 다 같이 막히는가 · 누가 멈췄는가」를 보려면 학생을 하나씩 열어야 했다.

**교재를 주인공으로** 다시 묶어 보여 준다.

## 1. 새로 모으는 자료는 없다

이미 있는 것만 읽는다.

| 무엇 | 어디서 | 쓰는 값 |
|---|---|---|
| 교재 목록·전체 쪽·끝낸 쪽 | `lumen_store` `mf_swb_<코드>`.books[] | `bid · swId · title · grade · pages[].{pid,page,st,title}` |
| 문항별 정오답 | `mf_answer_records` (`source='교재'`) | `student_workbook_id · workbook_page_id · number · level · result · score_datetime · lumen_rec_code` |
| 쪽 번호 | 위 둘을 **`workbook_page_id` ↔ `pages[].pid`** 로 이음 | 실제 교재 쪽 번호 |
| 아하노트 | `aha_notes` (앱이 이미 들고 있다) | 교재+쪽+문항번호로 정오답과 맞춤 |

`mf_answer_records.page` 는 `"32~63"` 같은 **범위**라 쪽으로 쓸 수 없다.
쪽은 반드시 `workbook_page_id → pid` 로 찾는다.

## 2. 집계는 새벽 서버가 한다 (앱은 요약만 읽는다)

5만 건을 앱이 열 때마다 읽으면 느리고, 서버(0.5GB)에도 부담이다
(`docs/incident_2026-09-18_supabase.md`). 그래서 **진도 레이스(`race_board`)와 같은 방식**으로,
서버가 미리 세어 `lumen_store` 한 칸에 넣어 둔다.

- 세는 곳: **`sync/book_dash_engine.js`**
- 저장 칸: `lumen_store` 키 **`book_dash`**
- 언제: 새벽 수집 뒤 자동 (`sync/collect_request_worker.js` 에 붙인다)
- 앱: 이 한 칸만 읽는다 → 화면이 바로 뜬다

**학생 이름은 저장하지 않는다.** 코드(`lumen_rec_code`)만 넣고, 이름은 앱이 등록부에서 붙인다.

### `book_dash` 의 모양

```
{ at, days, sum:{books,students,week,rate,prevRate,stalled},
  week:[월~일 문항수], levels:{1..5:{n,ok}},
  books:[ { bid, swId, title, grade, kind, nstu, pages, done,
            items, ok, rate, prevRate, last, state,
            levels:{1..5:{n,ok}},
            stus:[{code, done, pages, items, ok, rate, wrong, last, next}],
            map:[{p, n, ok, t}],          // 쪽 지도 (쪽·문항수·맞은수·단원)
            hot:[{p, stus, rate, t}] } ] } // 많이 틀린 쪽
```

`state` — 🟢`ok` · 🟡`hard`(정답률 65% 미만) · 🔴`stall`(며칠째 채점 없음) · 🏁`near`(90% 이상 진행)

## 3. 화면

### 3-1. 학원앱 PC — 「📗 교재 상황판」 새 탭

`진도·리포트` 그룹, **「📚 진도 현황」 바로 위**에 새 탭 하나.
기존 「📚 진도 현황」·「교재 채점」 화면은 **그대로 둔다**.

- **요약 띠 다섯 칸** — 쓰는 교재 n권 · 교재 푸는 학생 n명 · 이번 주 푼 문항(지난주 대비) ·
  평균 정답률(지난주 대비) · 🔴 멈춘 교재 n권
- **거르개** — 전체/중등/고등/초등 · 🔴 멈춤 · 🟡 정답률 낮음 · 정렬(최근 학습 순 기본) · 교재 검색
- **교재 표** — 교재 · 학생 수 · 진도 막대(끝낸 쪽/전체) · 정답률(▲▼) · 최근 학습 · 상태 배지
- **오른쪽** — ⚠️ 지금 신경 쓸 것 / 📈 이번 주 요일별 막대 / 🎯 난이도 1~5별 정답률

### 3-2. 교재 하나 펼쳐 보기 (교재 줄을 누르면)

- 머리: 전체 쪽 · 학생 수 · 누적 문항 · 평균 진도 · 평균 정답률 · 누적 오답 · 아하노트 수
- **학생별** (진도 느린 순) — 진도 막대 · 정답률 · 오답 수 · 마지막 학습 · **다음 할 쪽** · 눈여겨볼 것
- **🗺️ 쪽 지도** — 네모 하나 = 교재 한 쪽. 학생을 합친 쪽별 정답률로 색을 칠한다
  (🔴<50 · 🟠<70 · 🟡<85 · 🟢≥85 · 회색 = 아직 아무도 안 푼 쪽). 단원별로 줄을 나눈다
- **🔥 많이 틀린 쪽 Top 5** · **🎯 난이도별 정답률** · **💡 이 교재에서 올라온 아하노트**
  (아하노트의 교재·쪽·문항번호를 실제 ◯✗ 와 맞춰 「✗ → ◯ 다시 풀어 맞힘」까지 보여 준다)

### 3-3. 학원앱 폰 — 「📗 채점 현황」에 **칩 하나**

새 화면을 만들지 않는다. 지금 있는 `MOB.view='grd'` 의 갈래 칩에 **「교재별」**을 더한다.
- 요약 세 칸(쓰는 교재·평균 정답률·멈춘 교재) + ⚠️ 오늘 볼 것 + 거르개 칩
- 교재 카드 — 이름 · 상태 배지 · 진도 막대 · 학생 수 · 정답률(▲▼) · 한 줄 설명
- 카드를 누르면 그 교재의 학생 목록

## 4. 원장님이 정하실 것 — 기본값으로 시작한다

시안의 기본값 그대로 넣되, **화면에서 바꿀 수 있게** 한다(설정은 `lumen_store` `book_dash_cfg`).

| 정할 것 | 기본값 | 바꾸는 곳 |
|---|---|---|
| 교재 목록 정렬 | **최근 학습 순** | 화면 위 「정렬 ▾」 |
| 「멈춤」 기준 | **7일째 채점 없음** | 화면 위 「⚙ 기준」 |
| 들어가는 자리 | **PC 새 탭 「📗 교재 상황판」** | — |

## 5. 손대지 않는 것

- 매쓰플랫 수집기·되돌려쓰기(`hw_sync`)·워커의 기존 일
- 「📚 진도 현황」·「교재 채점(자기채점 훑어보기)」·로드맵·진도 레이스 화면
- 학생앱·학부모앱, 서버 표 구조 (새 표를 만들지 않는다 — `lumen_store` 한 칸만 더 쓴다)
- **시험지 규칙** — 학습지 문제 그림은 어디에도 띄우지 않는다

## 6. 확인 방법

실브라우저로 실제 자료를 띄워
① 교재 표의 학생 수·정답률이 그 교재 기록을 직접 센 값과 **같은지**,
② 쪽 지도의 쪽 번호가 `workbook_page_id → pid` 로 바르게 이어졌는지,
③ 진도(끝낸 쪽/전체)가 `mf_swb` 의 `st:'COMPLETE'` 개수와 같은지,
④ 멈춤 배지가 마지막 채점일과 맞는지,
⑤ 폰 「교재별」 칩이 기존 「학생별·학습지별」을 건드리지 않는지(회귀).
