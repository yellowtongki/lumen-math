# 📗 교재 상황판 — 계약서

원장 결정 2026-09-19: **시안(https://claude.ai/artifact/QfYtW8v8HsAHi2pmiGXoDd) 그대로 진행**.
학원앱 **v19-23** 한 버전에 담았다(v19-24 부터는 「📊 매쓰플랫 현황」 탭의 「📗 교재별」 칩).

## 0. 왜 만드는가

매쓰플랫 자동 수집으로 **교재 채점 기록 5만여 건**(`mf_answer_records`, `source='교재'`)이
이미 쌓여 있는데, 학원앱에서는 **학생 한 명씩** 밖에 볼 수 없었다.
「어느 교재에서 다 같이 막히는가 · 누가 멈췄는가」를 보려면 학생을 하나씩 열어야 했다.

**교재를 주인공으로** 다시 묶어 보여 준다.

## 1. 새로 모으는 자료는 없다

이미 있는 것만 읽는다.

| 무엇 | 어디서 | 쓰는 값 |
|---|---|---|
| 교재 목록·전체 쪽·끝낸 쪽 | `lumen_store` `mf_swb_<코드>`.books[] | `bid · swId · title · grade · recentPage · pages[].{pid,wpid,page,st,title}` |
| 문항별 정오답 | `mf_answer_records` (`source='교재'`) | `student_workbook_id · workbook_page_id · level · result · score_datetime · lumen_rec_code · mf_student_id` |
| 교재 묶기 | 기록 `student_workbook_id` ↔ `books[].swId` → `bid` | 같은 책은 학생이 달라도 `bid` 가 같다 |
| 쪽 번호 | 기록 **`workbook_page_id` ↔ `pages[].wpid`** | 실제 교재 쪽 번호 (`pages[].page`) |
| 재원생 | `lumen_store` `or_studentdb` | `withdrawn` 이 아닌 학생만 (이름은 쓰지 않는다) |
| 아하노트 | `aha_notes` (앱이 이미 들고 있다) | 교재+쪽+문항번호로 정오답과 맞춤 (앱에서) |

- `mf_answer_records.page` 는 `"32~63"` 같은 **범위**라 쪽으로 쓸 수 없다. 쪽은 반드시 `workbook_page_id → wpid` 로 찾는다.
- ⚠️ 쪽을 잇는 열쇠는 **`wpid`** 다. `pid` 는 학생마다 다른 배정 번호(progressId)라 기록과 맞지 않는다
  (실측 2026-09-19: 기록 `workbook_page_id=39885953` ↔ `pages[].wpid=39885953`, `pid` 는 678676994).
- 2026-09-18 이전 기록은 `lumen_rec_code` 가 비어 있을 수 있어 `mf_students`(매쓰플랫 학생ID → 코드)로 메운다.
  (2026-10-18 확인: 지금은 교재 기록 59,520건 모두 코드가 채워져 있다 — 안전장치로만 남긴다)

## 2. 집계는 서버가 한다 (앱은 요약만 읽는다)

5만 건을 앱이 열 때마다 읽으면 느리고, 서버(0.5GB)에도 부담이다
(`docs/incident_2026-09-18_supabase.md`). 그래서 **진도 레이스(`race_board`)와 같은 방식**으로,
서버가 미리 세어 `lumen_store` 한 칸에 넣어 둔다.

- 세는 곳: **`sync/book_dash_engine.js`** (`module.exports = { runBookDash, build, DEF_CFG }`)
- 저장 칸: `lumen_store` 키 **`book_dash`** — `at` 에 집계 시각(UTC ISO)을 적는다
- 언제: `sync/collect_request_worker.js` 가 돌 때마다(`mathflat-ondemand.yml`) `book_dash.at` 을 보고
  **180분보다 오래됐거나 칸이 비어 있으면** 다시 센다. 앱의 「🔄 다시 불러오기」는 읽기만 한다.
- 앱: 이 한 칸만 읽는다(`bdLoad`) → 화면이 바로 뜬다. **앱은 자체 계산을 하지 않는다** — 칸이 비면 「아직 집계가 없습니다」.
- 손으로 돌리기: `node sync/book_dash_engine.js` (저장) · `--dry` (계산만). 6만 건을 **읽기만** 하므로 낮에 돌려도 된다.

**학생 이름은 저장하지 않는다.** 코드(`lumen_rec_code`)만 넣고, 이름은 앱이 등록부에서 붙인다.
**로그에는 숫자만** 적는다(GitHub Actions 로그는 공개).

### `book_dash` 의 모양 (앱 v19-23~ 이 읽는 그대로)

```
{ at, cfg:{stallDays,idleDays,hardRate,nearPct,sort,mapTop},
  sum:{books,students,week,items,rate,stalled,hard,near,idle,live},
  week:[{d,n}×7],                 // 최근 7일 날짜별 푼 문항 수(교재만)
  levels:{1..5:{n,ok}},           // 전체 교재 난이도별
  books:[ { bid, title, grade, band:'elem'|'mid'|'high', kind,
            nstu, pages, avg, done, pgSum, prog,          // 학생 수 · 풀 쪽 수 · 평균 끝낸 쪽 · 진도 %
            items, n, ok, rate, delta, last, gone, state, // 누적 문항 · 채점 수 · 정답률 · 지난주 대비 · 마지막 채점일 · 며칠째
            lv:{1..5:{n,ok}},
            stus:[{code, done, pages, items, n, ok, rate, wrong, last, gone, round, next}],
            map:[{p, n, ok, i, s, t?}],   // 쪽 지도 (쪽·채점수·맞은수·문항수·틀린 학생 수·단원명은 바뀔 때만)
            hot:[{p, s, r, t}] } ] }      // 많이 틀린 쪽 (틀린 학생 수 · 정답률)
```

`state` — 🟢`ok` · 🟡`hard`(정답률 65% 미만) · 🔴`stall`(7일째 채점 없음) · 🏁`near`(진도 90% 이상) · ⬜`idle`(30일 넘게 손 안 댐 — 목록에서 접히고 쪽 지도를 싣지 않는다)
`rate`·`delta` 는 `null` 일 수 있다(채점 수가 적으면). `delta` 는 지난 7일 정답률 − 그 전 7일 정답률(둘 다 10문항 이상일 때만).

## 3. 화면

### 3-1. 학원앱 PC — 「📗 교재 상황판」

`진도·리포트` 그룹. (v19-24 부터 「📊 매쓰플랫 현황」 한 탭 안의 「📗 교재별」 칩 — 화면 내용은 같다.)
기존 「📚 진도 현황」·「교재 채점」 화면은 **그대로 둔다**.

- **요약 띠 다섯 칸** — 쓰는 교재 n권 · 교재 푸는 학생 n명 · 이번 주 푼 문항 · 평균 정답률 · 🔴 멈춘 교재 n권
- **거르개** — 전체/중등/고등/초등 · 🔴 멈춤 · 🟡 정답률 낮음 · 🏁 곧 끝 · ⬜ 보관 · 정렬(최근 학습 순 기본) · 교재 검색
- **교재 표** — 교재 · 학생 수 · 진도 막대(끝낸 쪽/전체) · 정답률(▲▼) · 최근 학습 · 상태 배지
- **오른쪽** — ⚠️ 지금 신경 쓸 것 / 📈 최근 7일 요일별 막대 / 🎯 난이도 1~5별 정답률

### 3-2. 교재 하나 펼쳐 보기 (교재 줄을 누르면)

- 머리: 전체 쪽 · 학생 수 · 누적 문항 · 평균 진도 · 평균 정답률 · 누적 오답 · 아하노트 수
- **학생별** (진도 느린 순) — 진도 막대 · 정답률 · 오답 수 · 마지막 학습 · **다음 할 쪽** · 눈여겨볼 것
- **🗺️ 쪽 지도** — 네모 하나 = 교재 한 쪽. 학생을 합친 쪽별 정답률로 색을 칠한다
  (🔴<50 · 🟠<70 · 🟡<85 · 🟢≥85). 아직 아무도 안 푼 쪽은 지도에 없다. 소제목은 도구말로.
- **📕 어려워하는 단원** · **🔥 많이 틀린 쪽 Top 5** · **🎯 난이도별 정답률** · **💡 이 교재에서 올라온 아하노트**
  (교재 이름이 달라도 브랜드+학년·학기로 느슨하게 잇는다)

### 3-3. 학원앱 폰 — 「📗 채점 현황」에 **칩 하나**

새 화면을 만들지 않는다. `MOB.view='grd'` 의 갈래 칩에 **「교재별」**을 더했다.
- 요약 세 칸(쓰는 교재·평균 정답률·멈춘 교재) + ⚠️ 오늘 볼 것 + 거르개 칩
- 교재 카드 — 이름 · 상태 배지 · 진도 막대 · 학생 수 · 정답률(▲▼) · 한 줄 설명
- 카드를 누르면 그 교재의 학생 목록

## 4. 원장님이 정하실 것 — 기본값으로 시작한다

시안의 기본값 그대로 넣되, **화면에서 바꿀 수 있게** 한다(설정은 `lumen_store` `book_dash_cfg`, 없으면 기본값).

| 정할 것 | 기본값 | 바꾸는 곳 |
|---|---|---|
| 교재 목록 정렬 | **최근 학습 순** | 화면 위 「정렬 ▾」 |
| 「멈춤」 기준 | **7일째 채점 없음** | `book_dash_cfg.stallDays` (화면 「⚙ 기준」은 아직 없음 — 서버 칸을 직접 적는다) |
| 보관 기준 | 30일 | `book_dash_cfg.idleDays` |
| 어려움·곧 끝 | 정답률 65% 미만 · 진도 90% 이상 | `book_dash_cfg.hardRate` · `nearPct` |

## 5. 손대지 않는 것

- 매쓰플랫 수집기·되돌려쓰기(`hw_sync`)·워커의 기존 일
- 「📚 진도 현황」·「교재 채점(자기채점 훑어보기)」·로드맵·진도 레이스 화면
- 학생앱·학부모앱, 서버 표 구조 (새 표를 만들지 않는다 — `lumen_store` 한 칸만 더 쓴다)
- **시험지 규칙** — 학습지 문제 그림은 어디에도 띄우지 않는다

## 6. 확인 방법

실브라우저로 실제 자료를 띄워
① 교재 표의 학생 수·정답률이 그 교재 기록을 직접 센 값과 **같은지**,
② 쪽 지도의 쪽 번호가 `workbook_page_id → wpid` 로 바르게 이어졌는지,
③ 진도(끝낸 쪽/전체)가 `mf_swb` 의 `st:'COMPLETE'` 개수와 같은지,
④ 멈춤 배지가 마지막 채점일과 맞는지,
⑤ 폰 「교재별」 칩이 기존 「학생별·학습지별」을 건드리지 않는지(회귀).
