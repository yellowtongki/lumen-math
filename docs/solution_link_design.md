# 오답 연결 「선생님 풀이」 설계안 — 이정민(명작수학) 방식의 루멘 적용

> 2026-08-01 작성 · 상의용 초안. 목업: `docs/mockup_solution_link.html`
> 핵심 원칙: **답지의 복제품을 만들지 않는다.** 풀이 자료는 "전 문제 아카이브"가 아니라
> **"내가 틀린 문제 · 질문한 문제"에 붙는 맞춤 풀이**로만 쓴다.

## ⭐ 2026-08-01 조정 — 매쓰플랫 프리미엄 확인 후 범위 축소

원장 확인 사항 두 가지로 계획을 좁힌다:
① 매쓰플랫 프리미엄(30명 30만원/월, 현재 15만원 대비 +15만원)은 **매쓰플랫에서 만든
모든 학습지 문항에 해설 영상을 자동 제공**한다. ② 루멘의 시험지는 대부분 매쓰플랫에서
만들고, 자체 자료는 시험대비 기간의 기출 정도뿐이다.

따라서:
- **3장 「풀이 자료실」(사진 대량 업로드·파일명 매칭·검수)은 만들지 않는다** — 존재 이유가
  "풀이 없는 문제를 대량으로 채우기"인데, 프리미엄이 매쓰플랫 문항 전부를 채워준다.
  몇 세트뿐인 기출을 위해 매칭 시스템을 만드는 것은 과함.
- **기출 풀이는 자체모의 탭(lumen_jamock)에 붙인다** — 이미 시험지·문항 구조가 있으므로
  문항에 풀이 사진 1장 첨부하는 작은 기능이면 충분 (시험대비 기간용).
- **루멘의 몫은 프리미엄이 못 하는 3가지로 확정**: ① 에빙하우스 복습 스케줄(언제 다시
  볼지) ② 원장 수업 영상의 문항 타임스탬프 ③ 아하노트 연동. 4장(학생앱 화면)과
  5장(타임스탬프)은 그대로 유효하고, 풀이 "콘텐츠"의 기본 소스는 프리미엄 영상이 된다.
- **프리미엄 가입 시 확인할 것**: 수집기가 보는 내부 API에 문항별 해설 영상 주소가
  내려오는지 → 내려오면 루멘 복습 카드에서 프리미엄 영상을 바로 여는 연동 시도.
  안 되면 "복습 카드에서 문항 확인 → 매쓰플랫 앱에서 영상 시청" 분업으로도 성립.
- 프리미엄 전환 여부·시점은 원장 결정 (권장: 1개월 체험 후 학생 시청 여부로 판단).

### ⭐⭐ 최종 범위 확정 (같은 날 추가 확인)

프리미엄 해설 영상은 **매쓰플랫에서 만든 학습지에만** 있고, **시중 교재(개념원리·쎈 등)
풀이는 없다** — 원장이 이 빈칸을 채우면 분업이 완성된다.

- **학습지 풀이는 1회용이지만 교재 풀이는 영구 자산** — 개념원리 p84 312번은 내년에도
  같은 문제. 한 번 만든 풀이가 학생·연도를 넘어 재사용된다 (이정민식 손풀이집의 본질).
- 따라서 3장 「풀이 자료실」을 **교재 전용으로 부활**한다 (학습지는 여전히 제외):
  - 「이번 주 많이 틀린 교재 문항 TOP」(수집된 교재 정오답 기반) + 아하노트 요청 목록이
    업로드 할 일 목록. 전체 채우기 아님 — 틀린 문제부터.
  - 파일명 규칙은 교재용만: `개념원리중2-2_84_312.jpg` (교재_쪽_번호)
  - 조인 키: 교재 문항 정오답(교재·쪽·번호) + 아하노트 동일 키 → 복습 카드·아하노트에 자동 연결
- 최종 분업: **학습지 영상=프리미엄 / 교재·기출 풀이=원장(루멘 자료실) / 복습 스케줄·
  수업영상 타임스탬프·아하노트 연결=루멘**

*아래 원안(1~7장)은 참고용으로 보존 — 3장은 교재 전용으로 축소 유지, 나머지는 유효.*

## 1. 이정민 시스템의 뼈대와 루멘식 번역

| 이정민(명작수학) | 루멘수학 적용 |
|---|---|
| 촬영 중 USB 발판을 밟아 문제 경계 표시 | 유튜브 업로드는 그대로 두고 **문제별 시작 시점(타임스탬프)** 을 기록 — 아래 2단계 |
| AI가 영상·PDF 대조해 단원·문제번호 매칭 | 루멘은 **매쓰플랫 수집 데이터에 이미 문항 정보가 있음**(학습지 문항번호·유형명) → 대조가 훨씬 쉬움 |
| 시놀로지 NAS(30TB)에 문제별 영상 저장 | 유튜브(영상) + Supabase Storage(손풀이 사진) — 서버 관리 불필요 |
| 학생은 번호 그리드에서 눌러 재생 | 루멘은 한 발 더: **정오답 데이터로 "내 오답"에만 자동으로 붙임** (이정민 시스템엔 없는 것) |
| 애매한 매칭은 후보 2~3개를 사람이 고름 | 동일 — 학원앱에 검수 화면 (아래 3-다) |

## 2. 데이터 설계

### 저장소
- **손풀이 사진**: Supabase Storage `photos` 버킷, `solutions/` 경로.
  업로드 시 긴 변 1600px 자동 리사이즈(학생앱 사진 업로드와 동일 규칙).
- **색인**: `lumen_store` 키 `sol_index` (SYNC_KEYS 등록, id 기준 합집합 병합·삭제 전파 안 함)

```
sol_index = {
  items: {
    "<solId>": {
      kind: "ws" | "book" | "exam",        // 학습지 / 교재 / 시험지
      ref:  { wid, num }                    // 학습지: worksheet_id + 문항번호
            | { book, page, num }           // 교재: 교재명 + 쪽 + 번호 (아하노트와 같은 형식)
            | { examId, num },              // 자체모의
      img:  "solutions/....jpg",            // 손풀이 사진 (없으면 null)
      vid:  { youtubeId, startSec },        // 영상 + 그 문제 시작 시점 (없으면 null)
      typeName: "직각삼각형의 합동 조건(RHS)",  // 유형명 (수집 데이터에서 자동)
      at: "업로드 시각", by: "teacher"
    }
  }, updated: ISO
}
```

### 문항과 짝짓기 (조인 키)
- **학습지 오답**: `mf_answer_records`의 `worksheet_id + number` ↔ `ref.wid + num` — 정확 일치.
- **교재 오답**: 수집된 교재 정오답(교재·쪽·번호) ↔ `ref.book + page + num`.
- **아하노트**: `aha_notes`에 이미 교재+쪽+문항번호가 있으므로 같은 키로 자동 연결.
- **요청 큐** `sol_requests`: 새벽 Routine이 ①아하노트 미해결 ②최근 7일 다수 오답 TOP을
  집계해 "풀이가 아직 없는 문항" 목록 생성 → 학원앱 업로드 화면의 할 일 목록.

## 3. 학원앱 — 「📸 풀이 자료실」 (신규 서브탭, 강의실 옆)

### 가. 업로드 우선순위가 화면에 보임 (답지 중복 방지의 실행 장치)
- 상단에 **「이번 주 풀이 요청 TOP」**: 다수 오답 문항(틀린 학생 수 순) + 아하노트 대기 문항.
  각 줄에 [📷 사진 올리기] [🎬 영상 시점 입력] 버튼 → 여기서 올리는 것이 기본 동선.
- 전체 문제를 채우는 화면은 만들지 않는다.

### 나. 사진 일괄 업로드 + 파일명 자동 매칭 (이정민식)
- 파일명 규칙(둘 중 편한 것):
  - 학습지: `0728_5.jpg` (날짜_문항번호 → 그날 학습지와 자동 대조)
  - 교재: `쎈2-2_84_312.jpg` (교재_쪽_번호)
- 규칙에 안 맞는 파일은 **AI(새벽 Routine)가 사진 속 문제번호·내용을 읽어 후보를 찾음**.

### 다. 검수 화면 (이상형월드컵식)
- 확실한 매칭(파일명 규칙 일치)은 바로 저장.
- 애매한 것만 「후보 검토 1/5」 화면: 원본 문항 정보 vs 후보 사진 2~3장 → 원장이 하나 클릭.
- 이정민 원장 방식 그대로 — "사람은 애매한 것만 고른다".

## 4. 학생앱 v2-21 — 붙는 자리 3곳 (목업 ①②③)

1. **오늘의 복습 카드**(에빙하우스): 틀린 문항에 [🎬 선생님 풀이]/[🖼 손풀이] 버튼.
   풀이 없는 문항은 "준비 중" — 자동으로 sol_requests에 올라감.
2. **풀이 화면**: 영상은 `youtube embed + start=초` 로 **그 문제 시점부터** 재생,
   아래 손풀이 사진(확대 가능), [📸 다시 푼 풀이 올리기](기존 재풀이 제출 재사용 → XP).
3. **아하노트**: 질문 문항에 풀이가 올라오면 배지 표시 + 바로 열기.

**답지와 다른 점(학생 시점)**: 전 문제 목록이 아니라 *내 오답·내 질문*에만 나타난다.
먼저 다시 풀게 유도(버튼은 접힌 상태로 시작하는 것도 검토), 재풀이 제출과 연결되어
"보고 끝"이 아니라 "다시 풀었는지"까지 기록된다.

## 5. 영상 타임스탬프 — 단계적으로

- **2-가 (수동, 바로 가능)**: 강의실 영상 편집에 「문항별 시점」 칸 추가.
  `5번 12:40 / 7번 18:25` 처럼 한 줄씩 붙여넣으면 파싱해 sol_index에 연결.
  유튜브 설명란에 챕터를 쓰는 습관과 같은 방식이라 추가 학습 비용이 없음.
- **2-나 (페달, 선택)**: 촬영용 맥에 발판(약 5만원)+매크로 → 밟을 때마다 경과시간을
  txt로 기록 → 그 파일을 시점 칸에 통째로 붙여넣기. 문항번호만 순서대로 매기면 끝.
- **2-다 (자동, 검증 후)**: 새벽 Routine이 신규 영상의 판서 화면을 분석해 문제 전환
  시점 초안 생성 → 원장 검수. (비용·정확도 확인 후 결정 — 처음부터 여기 걸지 않는다)

## 6. 단계별 실행 계획

| 단계 | 내용 | 결과물 |
|---|---|---|
| 1 | `sol_index`/`sol_requests` 설계 + 학원앱 「풀이 자료실」(TOP 목록·일괄 업로드·검수) | 학원앱 v17-2x |
| 2 | 학생앱 오답 복습·아하노트에 풀이 버튼 + 풀이 화면 | 학생앱 v2-21 (v1 교체는 원장님 판단) |
| 3 | 영상 문항별 시점 입력(수동) + 학생앱 시점 재생 | 학원앱·학생앱 |
| 4 | 새벽 Routine: 요청 큐 집계 + 사진 AI 매칭 + (검증 후) 타임스탬프 초안 | Routine 프롬프트 확장 |
| 5 | (선택) 페달 매크로 안내서 | docs/ 문서 |

## 7. 운영 원칙
- 업로드 대상: ① 답지 없는 자료(자체 프린트·시험지) ② 다수 오답 TOP ③ 아하노트 요청 — 이 순서만.
- 손풀이 사진에는 학생 이름·점수가 들어가지 않게 (판서/풀이만).
- 저장소에 사진 파일을 커밋하지 않는다 (Supabase Storage만).
