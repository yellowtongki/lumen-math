> 2026-10-18 원장 승인 설계 · 미리보기 https://claude.ai/artifact/92vDZYfvZ2ose8ad5rh66y · 코드 `sync/lumen_analyzer/`
> 지금 단계: **검증** (소사고 고1 먼저). 적중 분석 결과에는 아직 쓰지 않는다(`--apply` 는 원장님 승인 뒤).

## 1. 왜 만드나
지금 🎯 적중 분석 워커(`sync/exam_hit_worker.js`)는 시험 문항마다 «매쓰플랫 유형 번호(cid)가 같은 자료»만 후보로 골라 Claude 에게 그림 두 장씩 보여 준다.
소사고 고1 23번은 매쓰플랫이 같은 문제에 **다른 유형 번호**를 붙여 후보에 아예 못 올라갔다(수학비서 학평 문제지 2번 = 숫자변형).
수학비서처럼 **글자**로 비교하면 유형 번호가 달라도 찾는다.

## 2. 네 단계
| 단계 | 하는 일 | AI | 파일 |
|---|---|---|---|
| ① 글자 은행 | 문제 그림을 **한 번만** 글자로 옮겨 적어 저장, 계속 다시 쓴다 | Claude Sonnet 5.5 (서버) | `text_bank.js` |
| ② 뼈대 비교 | 숫자·문자 이름을 가린 «뼈대»를 세 글자씩 비교 → 같은문제 / 숫자변형 | 없음 | `match.js` |
| ③ 단원 비교 | 뼈대가 어중간하면 유형 번호·소단원(매쓰플랫), 단원 글자(수학비서) → 유사문제 / 같은유형 | 없음 | `match.js`, `run.js` |
| ④ AI 확인 | 애매한 쌍만 그림 판정 | 나중에 | — |

### 뼈대 만드는 법 (`match.js` `skeleton`)
1. 문제 번호·배점·보기(①~⑤) 를 뗀다.
2. 같은 집합을 다르게 쓴 것을 하나로: `{1,2,…,10}` = `{x|x는 10 이하의 자연수}` = `{x|1≤x≤10, x는 자연수}` → `{N}`
3. 숫자(소수 포함) → `#`
4. 대문자 한 글자(집합·점 이름) → 나온 순서대로 `V1, V2…`, 소문자 한 글자(변수) → `v1, v2…` (`n(A)` 의 n, 여집합 `^C` 는 그대로)
5. 기호 뒤 조사(이/가, 은/는 …)를 하나로, 띄어쓰기·문장부호·괄호를 뺀다.
6. 세 글자 묶음의 겹침(Jaccard). 대문자 이름 두 개를 맞바꾼 뼈대도 재 보고 가장 높은 값을 쓴다(「A−B」↔「B−A」 처럼 역할만 바뀐 쌍둥이).

기준 실험(소사고 고1 23번): 학평 2번(숫자변형) **0.76**, 다른 세 문제 **0.11~0.17** (`test_match.js`).

### 등급 기준 (`match.js` 의 `TH` — 검증 보고서를 보고 조정)
| 등급 | 조건 |
|---|---|
| 같은문제 `same` | 뼈대 ≥ 0.90 · 숫자까지 같음 · 질문 닮음 ≥ 0.5 |
| 숫자변형 `var` | 뼈대 ≥ 0.60 · 질문(구하는 것) 닮음 ≥ 0.5 |
| 유사문제 `sim` | 뼈대 0.35~0.60 · 같은 소단원(또는 같은 유형 번호) · 또는 뼈대 ≥ 0.60 인데 질문이 다름 |
| 같은유형 `type` | 유형 번호가 같거나 같은 소단원인데 뼈대는 덜 닮음 |
| 아님 `none` | 그 밖 |
- 글이 12글자보다 짧은(그림 위주) 문항이나 글자 은행에 아직 없는 문항은 **단원으로만** 본다(최대 «같은유형»).
- 학원앱 등급에는 «유사문제»가 없어서 `--apply` 때는 «같은유형»으로 넣고 이유 앞에 «유사»를 붙인다.

## 3. 저장 (lumen_store)
글자 은행은 «묶음마다 한 줄» — 문항마다 한 줄이면 수만 줄이 된다.

| 키 | 무엇 | 항목 키 |
|---|---|---|
| `ptx_exam_<시험>` | 시험 문항 | `exam:<시험>:<번호>` |
| `ptx_mp_<문제지>` | 수학비서 내 문제지 | `mp:<문제지>:<번호>` |
| `ptx_ms_<학습지>` | 수학비서 학습지 | `ms:<학습지>:<번호>` |
| `ptx_tb_<교재>` | 교과서 은행(학교 교과서 + 다른 출판사) | `tb:<문항 id>` (출판사 비교의 `pub:<id>` 와 같은 문항) |
| `ptx_ws_<학습지>` | 매쓰플랫 학습지 | `ws:<문항 id>` |
| `ptx_wb_<교재>` | 매쓰플랫 교재 | `wb:<문항 id>` |

값: `{ updated, model, items: { '<키>': { text, ask, choices:[…], fig, figNote, nums:[…], ocrAt, pid?, err?, from? } } }`
- 키는 적중 분석 워커의 자료 키와 같다. `from` = 같은 매쓰플랫 문항(같은 그림)을 다른 자리에서 이미 옮겨 적어 글을 빌려 온 것(돈 안 듦).
- `err` = 그림을 못 받았거나 Claude 가 거절(refusal)한 것. `--retry-err` 로 다시.
- 검증 보고서: `analyzer_report_<시험>` (`{ pass, counts, coverage, items:[…], md }`).

## 4. 실행
### GitHub Actions (권장 — API 열쇠가 서버에만 있다)
Actions → «🔤 루멘 분석기» → Run workflow
- `exam` 시험 id (예 `소사고_고1_2026_2_중간`)
- `mode` `bank`(글자 은행만) · `report`(보고서만) · `both`(기본)
- `limit` 이번에 옮겨 적을 최대 그림 수(비우면 전부 — 이어 하기가 되므로 나눠 돌려도 된다)
- `scope` `exam`(기본, 매쓰플랫 자료도 시험 범위 소단원만) · `all`(이번 학기 푼 것 전부)
- 결과: 실행 화면 아래 **Artifacts › analyzer-report** (report.md · report.json, 학습지 제목 없음) + lumen_store `analyzer_report_<시험>` (제목 포함)
- ⚠ `workflow_dispatch` 는 이 파일이 **main 에 있어야** Actions 화면에 단추가 생긴다.
- 정기 수집·요청 처리와 같은 줄(`mathflat-collect`)에 서서 매쓰플랫 로그인이 겹치지 않는다. 120분 제한.

### 명령줄
```
node sync/lumen_analyzer/text_bank.js --exam 소사고_고1_2026_2_중간 --dry        # 몇 장 옮겨 적을지·예상 비용만 (AI 안 씀)
node sync/lumen_analyzer/text_bank.js --exam 소사고_고1_2026_2_중간 [--limit 300] [--scope exam] [--no-pub] [--retry-err]
node sync/lumen_analyzer/run.js --exam 소사고_고1_2026_2_중간 [--report 폴더] [--no-save] [--scope exam] [--bank-file 덧씌울글.json]
node sync/lumen_analyzer/test_match.js                                               # 뼈대 비교 검사 (네트워크 없음)
```
이 컨테이너(채팅)에는 API 열쇠가 없어 ①은 GitHub 에서만 돈다. `--bank-file` 로 채팅에서 옮겨 적은 글을 덧씌워 ②③만 시험해 볼 수 있다.

### 소사고 고1 규모 (2026-10-18 `--dry`)
| 범위 | 대상 | 서로 다른 그림 | 예상 비용 |
|---|---|---|---|
| `--scope all` (출판사 교과서 포함) | 3,936 | 3,727 | 약 $14~21 |
| `--scope exam` (출판사 교과서 포함) | 3,431 | 3,222 | 약 $12~18 |

비용 계산: Sonnet 5.5 입력 $2/M · 출력 $10/M, 그림 한 장 입력 약 1,100~1,500 토큰(그림 400~800 + 규칙 글) · 출력 150~250 토큰. 한 번 옮겨 적은 것은 다른 시험에서 다시 쓰므로 두 번째 시험부터는 훨씬 싸다.

## 5. 보고서 읽는 법 (`report.md`)
- 맨 위 **결과**: 통과 기준 «놓침 0 · 잘못 찾음 2 이하» (원장 2026-10-18).
  - **놓침** — 원장님이 «같은문제·숫자변형»으로 ✓ 확정한 자료가 분석기 위 6개 안에 같은문제·숫자변형으로 없다.
  - **잘못 찾음** — 분석기는 같은문제·숫자변형이라 했는데 원장님은 «적중 없음» · ✗ · «유형만»으로 확정.
  - **새로 찾음** — 학원앱 후보에 없던 자료를 분석기가 같은문제·숫자변형이라 함 → 원장님 확인 필요(진짜면 워커가 놓친 것).
  - **일치** — 원장 적중을 분석기도 같은문제·숫자변형으로 찾음.
- **글자 은행 채움** — 글이 없는 문항은 단원으로만 비교했으니 숫자가 낮으면 bank 부터.
- **문항별 표** — 원장 확정 · 지금 워커 1순위 · 분석기 1순위(이유: `뼈대 0.76(이름 바꿈) · 질문 같음`) · 2~3순위.
- 출판사 교과서 적중(학원앱 «출판사» 칸, `pub:<id>`)은 교과서 은행의 `tb:<id>` 와 같은 문항으로 맞춘다.
