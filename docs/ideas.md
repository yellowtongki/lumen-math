## 🌱 1. 학생별 개별 진도표 → 주간계획표 숙제 배분

**등록일**: 2026-08-20 · **제안**: 원장님

### 원문
> 학생별 개별 진도표가 필요하다. 하루에 어떤 문제집을 몇 문제씩 풀지 학생 개별앱에
> 캘린더 형식의 주간계획표에 넣어서 숙제 배분하기. 수학뿐만 아니라 다른 숙제도
> 학생이 넣을 수 있게. 주간계획표 작성과 연동 또는 합치고 싶다.

### 한 줄 요약
선생님이 "이 학생은 이번 주에 쎈 82~89쪽, 하루 15문제" 식으로 배분하면
→ 학생앱 주간계획표 달력에 날짜별로 자동으로 꽂히고
→ 학생은 거기에 자기 숙제(영어 단어, 학교 수행평가 등)를 직접 얹는다.

### 지금 앱에 이미 있는 것 (2026-08-20 확인)
| 조각 | 위치 | 상태 |
|------|------|------|
| 주간계획표 화면 | 학생앱 `#screen-weekplan` (v1-28 때 만든 골격) | 화면·달력 그리드·목표카드·자동추천 버튼까지 있으나 **저장이 연결 안 됨** |
| 플래너 안의 주간계획표 탭 | 학생앱 플래너 화면 `pl2-t2` | 🚧 "주간계획표 준비중" 안내만 뜸 |
| 교재 진도 | `bookprog_<학생코드>` (Supabase `lumen_store`) | 동작 중 — 학생별 교재 진행률 |
| 교재 목록 | `or_books` | 동작 중 |
| 숙제 4단계 스테이지 | 학원앱 `homeworkCheck` | 동작 중 — 풀이→채점→오답→아하노트 |

즉 **주간계획표가 두 군데에 흩어진 채 미완성**이라, "연동 또는 합치고 싶다"는
원장님 말씀이 정확하다. 이 아이디어는 사실상 *주간계획표를 완성시키는 일*이다.

### 결정이 필요한 것 (개발 전에 원장님 판단)
1. **누가 배분하나?**
   - (A) 선생님이 학원앱에서 배분 → 학생은 보기만 (통제 강함)
   - (B) 선생님은 "이번 주 범위"만 주고 학생이 요일에 나눔 (자기주도 훈련)
   - (C) 선생님이 자동 배분해두고 학생이 옮길 수 있음 ← 아마 이게 현실적
2. **배분 단위**: 문항 수(15문제)? 페이지 수(3쪽)? 둘 다?
3. **비수학 숙제**: 과목 자유입력? 아니면 영어/국어/과학… 고정 목록?
4. **완료 체크**: 학생이 체크만? 플래너 사진 제출과 자동 연결? XP 지급?
5. **밀린 숙제**: 못 한 분량을 다음 날로 자동 이월할지

### 예상 데이터 구조 (초안)
```
lumen_store 키: weekplan_<학생코드>_<주차>   예: weekplan_A3F9K2_2026-W34
{
  goal: "이번 주 각오",
  days: {
    "2026-08-24": [
      { type:"math", book:"쎈 중2-1", from:82, to:85, count:15, done:false, by:"teacher" },
      { type:"etc",  subject:"영어", title:"단어 100개", done:true,  by:"student" }
    ]
  }
}
```
- `by`로 선생님 배분(수정 불가)과 학생 추가(자유 편집)를 구분
- 수학 항목은 `bookprog_<code>`·매쓰플랫 정오답과 연결 여지 있음

### 연결되는 다른 계획
- 매쓰플랫 정오답 자동 연동 → **에빙하우스 복습 스케줄러**가 만드는 "오늘의 복습"도
  결국 이 주간계획표 달력에 꽂혀야 자연스럽다. 두 기능은 같은 달력을 써야 함.
- 학부모앱에 "이번 주 우리 아이 계획/실행률" 노출 가능

### 규모 감
학생앱 한 화면을 제대로 만들고 + 학원앱에 배분 화면을 새로 만드는 작업이라
**작은 수정이 아니라 하나의 프로젝트**. 매쓰플랫 연동이 어느 정도 자리 잡은 뒤
착수하는 편이 좋아 보임 (복습 카드까지 같은 달력에 얹으려면).

## 🌱 2. 블로그·인스타 자동화 — 글은 Claude, 이미지·영상은 GPT와 협업

**등록일**: 2026-08-20 · **제안**: 원장님

### 원문 요지
> 목표는 블로그 자동화 + 인스타 자동화. 이미지 생성은 제미나이 품질이 떨어졌고
> 클로드는 이미지를 못 만드니 GPT를 쓴다. 동영상·이미지 제작은 Claude만으로 부족해서
> GPT와 협업. 블로그 자동화는 다른 채팅에서 "클래스바이"가 만들어준 것을 쓰고 있음 → 추후 연결.

### 역할 분담 (핵심 결론)
| 일 | 담당 | 이유 |
|----|------|------|
| 주제 잡기·글쓰기·해시태그·프롬프트 작성·조립·업로드 | **Claude (Claude Code)** | `docs/blog_writing_context.md`에 톤이 이미 정리돼 있음 |
| 사진풍·일러스트 이미지 | **GPT 이미지 API** | Claude는 이미지 생성 불가 (사실) |
| 카드뉴스·텍스트 들어간 이미지·도표 | **Claude (HTML → 스크린샷)** | 생성형 AI는 한글 글자를 자주 깨뜨림. HTML로 그려 찍으면 글자가 정확함. 이 환경에 Chromium·Playwright 이미 있음 |
| 짧은 영상(릴스) | 1차: 이미지+자막 슬라이드 영상(Claude가 조립) / 2차: 생성형 영상 도구 | 생성형 영상은 아직 비용·품질 편차 큼 |

### 필요한 준비물
- **OpenAI API 키** (ChatGPT 구독과 별개, 사용량 과금). 환경변수 `OPENAI_API_KEY`로만 보관 — 저장소에 절대 넣지 않음
- 인스타 자동 게시: **Instagram Graph API** — 비즈니스/크리에이터 계정 + 페이스북 페이지 연결 + 이미지가 공개 URL에 있어야 함 (GitHub Pages나 Supabase Storage로 해결 가능)
- 네이버 블로그는 공식 글쓰기 API가 없음 → "클래스바이" 자동화가 어떤 방식인지(브라우저 자동화? 다른 플랫폼?) 확인 필요

### 클래스바이 블로그 자동화와 연결하는 법 (추후)
Claude 채팅끼리는 서로 기억을 공유하지 않는다. 그 채팅에서 **만든 스크립트/설명 파일을
이 저장소 `docs/` 또는 `sync/`에 넣어두면** 여기서 바로 이어서 볼 수 있다.
그 채팅에 "지금까지 만든 자동화 구조를 파일 하나로 정리해줘"라고 하면 됨.

### 예상 파이프라인 (초안)
```
원장님: "이번 주 블로그 주제는 예비고1 내신 대비"
 → Claude: 글 초안 (blog_writing_context 톤) + 이미지 프롬프트 3개
 → sync/image_gen.js: GPT 이미지 API 호출 → PNG 저장
 → Claude: 인스타용 카드뉴스 4장 (HTML 렌더 → PNG)
 → 원장님 확인 (검수 단계는 반드시 사람이)
 → 게시: 인스타 Graph API / 블로그(클래스바이 방식)
```

### 먼저 정할 것
1. 블로그 플랫폼이 네이버인지 (자동 게시 방식이 완전히 달라짐)
2. 인스타 계정이 비즈니스/크리에이터로 전환돼 있는지
3. 검수 없이 완전 자동 게시할지, 원장님 확인 후 게시할지 (**확인 후 게시 권장**)

### 📌 2026-09-08 업데이트 — 원장님 답변 + 도구 조사
- **블로그 = 네이버 확정.** 네이버 공식 글쓰기 API는 2020년 종료 → 모든 자동화는
  브라우저 자동 조작(Playwright) 방식. 클래스바이 도구도 십중팔구 같은 방식.
  공개 MCP 예: `space-cap/naver-blog-mcp` (아이디/비번 로그인, 글쓰기·이미지 업로드·카테고리,
  세션 24시간 재사용). **경고**: 캡차 발생 가능, 과도한 자동화는 계정 제재 위험.
  → 자동 "게시"보다 자동 "초안 작성 + 이미지 준비"까지만 하고 게시 버튼은 사람이 누르는 설계 권장.
- **힉스필드(Higgsfield) MCP** — Claude Code에 직접 연결 가능 (`claude mcp add higgsfield …`,
  브라우저 로그인 인증). 이미지(Flux·Seedream·Soul 등)와 **영상(Kling·Veo·Seedance, 최대 15초)**
  30개+ 모델. 크레딧 과금, 3일 무료 100크레딧.
  → **역할 분담 수정**: "이미지는 GPT" 대신 **Claude + 힉스필드**로 이미지·영상 모두 해결 가능.
  GPT를 다리로 쓸 필요가 없어짐. 단 한글 글자 이미지(카드뉴스)는 여전히 HTML→PNG로.
  → 주의: 이 클라우드 작업환경은 힉스필드 접속이 막혀 있어, 실제 연결·테스트는
  원장님 컴퓨터의 Claude Code에서 해야 함.
- **인스타 게시 MCP** — 공식 Graph API 직접 연결 외에 중개 서비스가 여럿 (Blotato, Markifact,
  Upload-Post, Composio, Contentdrips). 단일 이미지·캐러셀(2~10장)·릴스·스토리 + 예약 게시 지원. 유료.

### 📌 2026-09-09 — 클래스바이 블로그 도구 전체 파악 완료
전체 분석 문서를 `docs/blog_automation_overview.md`로 저장함 (원장님 컴퓨터 Claude가 실제 설치 파일을 열어보고 작성).
아래는 **우리 계획에 영향을 주는 부분만** 추린 것.

**도구의 정체**
- 난독화된 Node 프로그램. 부품은 MCP SDK · Playwright(크롬 리모컨) · zod 셋뿐.
  **그림 생성 AI가 하나도 없음** — 카드는 웹페이지를 만들어 캡처(`rendered.html` 실존).
- 무단 수정·역난독화는 라이선스 위반 → **내부를 고치지 말고 바깥에서 연결**한다.
- 네이버 **임시저장까지만** 하고 발행은 원장님이 직접. 하루 1개 제한(임시저장 순간에만 차감,
  글 다시 쓰기·미리보기는 무제한). 저장에 8~14분 (사람 타자 속도 흉내).

**⭐ 가장 큰 발견 — 인스타 콘텐츠가 이미 만들어지고 있다**
카드 6장이 **1080×1350 또는 1080×1080**(= 정확히 인스타 규격)으로 만들어져
`~/.classby-blog-studio/out/<글별 폴더>`에 쌓인다. 즉 **블로그 글 한 편 = 인스타 캐러셀 한 개가 이미 완성돼 있음.**
→ 인스타 자동화의 남은 일은 "만들기"가 아니라 **그 폴더의 PNG를 인스타로 올리는 것**뿐. 난이도가 확 낮아짐.
→ 게다가 도구가 **카드+실사진을 이어붙인 무음 슬라이드쇼 영상**도 이미 만들어 글 맨 아래에 넣는다
   (릴스 원본으로 전용 가능). 지난번 계획의 "1차 슬라이드 영상"은 이미 있는 셈.

**우리가 채워야 할 진짜 빈칸 3개**
1. **인스타 게시** — out 폴더 → 캐러셀 업로드 (Graph API 또는 중개 서비스 MCP)
2. **글감(학원 데이터)** — 4단계 "주제 고르기"·5단계 "카드 글"에 학원앱 집계 수치를 넣어주기.
   카드 종류에 **"수치" 카드**가 있는데 우리 앱은 수치가 넘친다 (오답 유형, 정답률, 리커버리 등).
3. **실사진 3장 이상** — 도구의 필수 검사 항목이고 안 주면 자리만 비어 원장님이 손으로 끼워야 함.
   → 학원앱에 이미 사진이 있음(플래너 제출 사진, 아하노트 사진). **단 학생 개인정보라 그대로 쓰면 안 됨.**
     이름·얼굴 없는 풀이 노트 클로즈업만, 원장님 확인 후 사용. 별도 "블로그용 사진함" 만드는 게 안전.
   → ⚠️ **AI로 학원 내부 사진을 지어내는 것은 금지** (실사진 자리에 가짜 사진 = 허위 광고).
     힉스필드는 개념 삽화·배경 이미지에만 쓴다.

**주의사항 (도구의 규칙)**
- 검색 질문은 **글자 하나까지 그대로** 써야 인식됨. 도구가 주는 `"옥길중 내신 수학는"`은 맞춤법이
  틀렸지만 고치면 저장이 막힘 → 클래스바이에 수정 요청할 항목.
- 카드에 넣은 질문은 **본문에도 글자로** 있어야 함 (카드는 그림이라 검색엔진이 못 읽음).
- `profile.json`(학원 정보·말투 원문) 폴더는 **지우면 안 됨**.
- **학원법**: 모집 목적 글에는 교습비·등록번호·학원명·교습과목 표시 의무 (미표시 과태료 300만원 이하).
  여기서 교습비는 등록 금액이 아니라 **학생이 실제 내는 금전 일체**(교재비 포함). 프로필에 한 번 넣으면 자동 삽입.
- 도구는 원장님 말을 사실로 믿음 → 숫자·연도는 사람이 확인. 미확정은 `{{미확정:이름}}`으로 비워둠.

**말투 자료 중복 정리 필요**
`profile.json`에 말투 원문이 저장돼 있고, 이 저장소에도 `docs/blog_writing_context.md`가 있음.
둘이 어긋나면 글 톤이 흔들리므로 **한쪽을 원본으로 정하고 다른 쪽은 참조**로 둘 것.

**대기 중**: 그 컴퓨터 채팅에서 아하노트 소개 블로그 글이 카드 선택 단계에서 멈춰 있음.

| 컴퓨터 Claude 데스크톱 앱 | ❌ | (도구 통해서만) | ✅ 등록됨 |
| **컴퓨터 Claude Code** (2026-09-09 설치함) | ✅ 클론하면 | ✅ | ⬜ 꽂으면 가능 |

- 블로그 도구는 **MCP**라는 규격의 부품이라 **여러 채팅 프로그램에 각각 꽂을 수 있다.**
  지금은 데스크톱 앱 설정(`claude_desktop_config.json`의 mcpServers)에만 꽂혀 있음.
  Claude Code에도 따로 꽂으면 **한 자리에서 저장소 + 컴퓨터 파일 + 블로그 도구**를 다 다룰 수 있다.
- 즉 **컴퓨터의 Claude Code가 다리**다. 인스타 업로드 스크립트는 결국 여기서 돌려야 한다
  (카드 PNG가 컴퓨터 `out` 폴더에 있으므로).
- 클라우드 채팅(여기)은 여전히 학원앱 개발과 Supabase 데이터 글감 뽑기에 쓴다.
- ⚠️ 도구 재등록(`등록하기.bat`)은 **Claude를 완전히 끈 상태에서** 할 것.

### 학원과 결합했을 때 시너지 (콘텐츠 원천을 학원앱 데이터로)
다른 학원이 못 따라 하는 부분은 도구가 아니라 **글감이 앱에서 자동으로 나온다**는 점.
| 앱 데이터 (익명화) | 콘텐츠 |
|---|---|
| 유형DB·정오답 → 이번 주 최다 오답 유형 | "이번 주 부천 중2가 가장 많이 틀린 문제 유형 TOP3" 카드뉴스 |
| 아하노트 질문 | "학생 질문 베스트" 릴스 (힉스필드 영상 + 자막) |
| 진학 나침반 (부천 고교별 예상 내신) | 부천 고교 입시 정보 시리즈 → 지역 검색 유입 |
| 리커버리·주간테스트 운영 | 이미 쓴 블로그 톤 그대로 시스템 소개 시리즈 |
| 학부모앱 리포트 | "루멘 학부모는 이런 리포트를 받습니다" 샘플 공개 |
| 공지(`lumen_announcements`) | 인스타 스토리 자동 변환 |
**절대 규칙**: 학생 이름·개별 점수는 콘텐츠에 넣지 않음. 집계·익명 수치만.

## 🌱 3. 유웨이 입시매니저 — 고등부 대입 상담 도구를 학원앱과 잇기

**등록일**: 2026-09-15 · **제안**: 원장님 (유웨이 교육과정 수료 후 학생 상담에 활용 예정)

### 원문 요지
> 유웨이 입시매니저를 수강·수료하고 학생들에게 해줄 계획. 학원앱에 추가 가능한가, 따로 해야 하나?
> 고1·2 수시 컨설팅도 가능한가?

### 보내주신 문서의 정체
자격증 안내문이 아니라 **입시매니저(manager.uway.com) 교사용 사용 매뉴얼** 39쪽.
유웨이 교육과정을 이수하면 입시매니저 계정 **할인 쿠폰**을 받는 구조 (7쪽).

### 프로그램이 하는 일
학생의 내신·모의고사 성적을 넣으면 → 성적분석 / 수능지수 / 수시·정시 유불리 / 합격진단 /
AI 추천대학 / 목표성적진단 → **상담 리포트 출력**. 자소서 유사도 검사는 별도 상품.

### 학원앱에 넣을 수 있나 — "안에 넣기"는 불가, "다리 놓기"는 가능
- 공개 API 없음. 웹사이트에 로그인해서 쓰는 방식 → 학원앱 화면 안에 넣는 건 안 됨.
- 대신 **양쪽 끝을 학원앱이 받쳐줄 수 있음**:
  1. **학원앱 → 입시매니저**: 학생 명단 양식(이름/성별/졸업연도/연락처/이메일)과 내신 양식(교과/과목/단위수/석차등급)을
     엑셀로 내보내기. 단 학원앱 `school_scores`는 **수학 성적만** 저장함 → 나머지 과목은 원장님이 직접 입력.
  2. **입시매니저 → 학원앱**: 출력한 상담 리포트 PDF를 학원앱에 올려 학부모앱으로 발행.
     매쓰플랫 월간 리포트(`lumen_mf_reports`) 방식 그대로 재사용 가능.
  3. **진학 나침반과 연결**: 나침반은 중→고(부천 고교 예상 내신), 입시매니저는 고→대. 둘을 이으면
     "중2부터 대학까지" 흐름이 생김. 학원앱에 🎓 대입 탭을 두고 고등 내신·모의고사 저장 + 리포트 보관.

### 고1·2 수시 컨설팅 가능한가 — 절반은 됨
| 되는 것 (숫자 기반) | 안 되는 것 (도구 밖) |
|---|---|
| 내신 등급 → 교과전형 지원권 진단 | 학종 설계(선택과목·세특·활동 계획) |
| 목표성적진단 (목표 등급 → 지원권) | 정성 평가 요소 판단 |
| 수시/정시 유불리 비교 | 학교별 교육과정 상담 |
- ⚠️ **2028학년도 대입 개편** — 현재 고2(2025년 입학)부터 내신 5등급제·통합형 수능 적용.
  입시매니저 예측은 "전년도 입시결과" 기반이라 **새 제도를 얼마나 반영하는지 유웨이에 반드시 확인**.
- 자소서는 2024학년도부터 대입에서 폐지 → 매뉴얼의 자소서 유사도 검사는 현재 쓸 일 거의 없음 (매뉴얼이 오래됐을 가능성).

### 비용 구조 (매뉴얼 6~7쪽)
1계정 = 학생 1명, 학년별 구매. **학원 최소 10계정**, 30계정 이상 할인. 학생정보 등록 순간 계정 소모(재사용 불가).
신용카드 결제, 견적서 7일 유효. → 고등부 10명 이상일 때 실익.

### 유웨이에 물어볼 것
1. 2028 대입 개편(5등급제·통합수능) 반영 여부와 시점
2. 교육과정 이수 할인 쿠폰의 할인율과 계정 최소 수량 적용 여부

### 다음 단계 (착수 시)

## 🌱 4. 백지테스트 자동 생성 — 내용을 만들어 채우기

**등록일**: 2026-09-20 · **제안**: 원장님 (아이폰 메모)

### 원문
> 구글드라이브에 이론쓰기 파일과 교재나 수학비서 기출에 연계해서 자동으로 백지테스트를
> 만들어서 저장하거나 저장된 세트를 배포하는 기능만 할 수 있다.
> 유튜브 링크와 연동해서 내 강의 내용에서 중요한 것을 읽어서 데이터화.

### ⭐ 확인 결과 — "배포"는 이미 다 만들어져 있다 (v19-26 기준)
| 원장님이 원한 것 | 앱의 현재 상태 |
|---|---|
| 백지테스트 **배포** | ✅ **이미 있음** — 할 일 보드(칸반)의 단계 종류 7가지 중 `blank` 📝 백지테스트. 학생이 사진으로 제출 |
| 수학비서 **기출 연계** | ✅ **이미 있음** — 🏭 기출 쌍둥이 공장 (수학비서 기출 → 매쓰플랫 원본+쌍둥이 학습지 자동 생성) |
| **유튜브 링크** 관리 | ✅ **이미 있음** — `vod_catalog`에 `youtubeId`, 영상 완주하면 카드가 자동 제출됨 |
| 백지테스트 **내용 자동 생성** | ❌ **없음** ← **이것이 진짜 빈칸** |
| 구글드라이브 **이론 파일** 읽기 | ❌ 없음 |

> `docs/todo_board_contract.md`(2026-09-20 원장 결정)에 이미 적혀 있음:
> "백지테스트는 **개념 백지 + 틀린 유형 재풀이 둘 다**(②에서)".
> 즉 이 아이디어는 **새 기능이 아니라 그 ②단계를 채우는 일**이다.

### 그래서 만들 것은 하나뿐
**단원을 고르면 백지테스트 문항을 만들어 세트로 저장하는 기능.**
저장된 세트 id를 칸반 단계의 `ref`에 넣으면 배포는 기존 보드가 그대로 해준다 (새로 만들 필요 없음).

```
단원 선택 (예: Ⅲ. 일차부등식)
  → 출처에서 핵심 개념 뽑기
  → 백지 문항 생성 ("부등식의 양변에 음수를 곱하면 어떻게 되는가?" 등)
  → 세트로 저장 (lumen_store: blank_sets)
  → 칸반 단계 ref에 연결 → 학생앱 카드로 배포 (기존 기능)
```

### 출처별 현실성 — 정직한 평가
| 출처 | 정확도 | 판단 |
|---|---|---|
| **유형DB**(`lumen_type_db`) | 높음 | ⭐ 이미 구조화된 데이터. 여기부터 시작 |
| **원장님 이론 파일**(구글드라이브) | 높음 | ⭐ 원장님이 직접 쓴 것이라 가장 정확. 드라이브 연결은 이미 있음 |
| **수학비서 기출** | 중간 | 문제는 있지만 "개념"이 아니라 "문항"이라 변환 필요 |
| **유튜브 강의 자막** | **낮음** | ⚠️ 아래 참고 |

### ⚠️ 유튜브 강의 → 데이터화는 기대보다 어렵다
- 수학 강의의 **핵심은 판서**인데 자막에는 안 잡힌다. 음성은 "이거를 이렇게 넘기면"처럼만 나온다
- 한국어 자동 자막은 수학 용어에서 오류가 많다 (근의 공식, 판별식 등)
- 1시간 영상에서 핵심을 뽑아도 **유형DB에서 뽑는 것보다 정확하지 않을 가능성이 높다**
→ **유튜브는 마지막에.** 하려면 자동 자막 말고 음성인식(Whisper 등)을 써야 하고,
  그래도 판서 내용은 못 읽으므로 **원장님이 영상마다 핵심 3줄만 적어두는 편이 훨씬 정확하고 빠르다.**

### 권장 순서
1. **유형DB → 백지 문항 생성** (가장 정확, 데이터 이미 있음)
2. **구글드라이브 이론 파일 읽기** 추가 (원장님이 쓴 원본이라 품질 최상)
3. 세트 저장 + 칸반 `ref` 연결 (배포는 기존 보드가 처리)
4. 기출 연계 (쌍둥이 공장과 묶기)
5. 유튜브 — 실효성 재검토 후 판단

### 먼저 확인할 것
- 구글드라이브의 "이론쓰기 파일"이 어떤 형식인지 (한글? 워드? 구글 문서? 손글씨 사진?)
- 백지테스트 문항 형태: 서술형("~을 설명하시오")인가, 빈칸 채우기인가, 둘 다인가

## 🌱 5. 수행평가 도우미 (수학)

**등록일**: 2026-09-20 · **제안**: 원장님

### 원문
> 이미 학원앱에는 학교알리미가 연동이 되어있다. 수행평가 도우미를 만들자. 나는 수학이다.
> 설계가 가능한지와 이 아이디어가 학원앱 세션과 연계가 되는가?

### ⚠️ 먼저 정정 — 지금 연동된 "학교알리미"는 다른 항목이다
| | 지금 앱이 쓰는 것 | 수행평가 도우미에 필요한 것 |
|---|---|---|
| 출처 | 학교알리미 **성적 분포** (평균·A~E 비율) | 학교알리미 **「교수학습 및 평가 운영 계획」 공시** |
| 쓰는 곳 | 진학 나침반, 모의 성적표 | (아직 없음) |
| 방식 | 캡처 이미지 → AI 비전 추출 | 공시 파일 파싱 |

또 `school_calendar`(시험일)는 **학교알리미가 아니라 NEIS**(open.neis.go.kr)에서 온다.
→ 즉 **파이프라인은 있지만 이 항목은 아직 안 쓰고 있다.** 새로 붙여야 한다.

### 평가계획 공시에 실제로 들어 있는 것 (확인됨)
- 지필/수행 **반영 비율**, 중간·기말 실시 여부
- **수행평가 영역 개수와 영역별 비율**
- 수행평가 **명칭 · 평가 요소 · 채점 기준 · 배점**
- 단원명 · 성취기준 · 수업 방법
- 형식: **hwp · hwpx · pdf · zip · txt** / 공시 시기: **4월 말(1학기) · 9월 말(2학기)**

> ⏰ **지금이 9월 말** — 2학기 평가계획이 막 올라오는 시기다. 타이밍이 좋다.

### 학원앱과의 연계 — 강하게 된다
| 이미 있는 것 | 수행평가 도우미에서 쓰는 방법 |
|---|---|
| 학교알리미 캡처 → AI 비전 추출 | **그대로 재사용.** 평가계획도 캡처해서 읽으면 됨 |
| `school_calendar` (NEIS 시험일) | 지필 시험일 + 수행평가 일정을 **한 달력**에 |
| 칸반보드 (`todo_courses`, 단계 7종) | 수행평가 준비를 **`etc` 또는 새 단계**로 배포 |
| `or_studentdb` (학생별 학교·학년) | 학생마다 **자기 학교 것만** 보이게 |
| 학부모앱 발행 구조 | "○○중 2학기 수학 수행평가 안내" 리포트 |
| 진학 나침반 | 내신 산출에 수행평가 비율 반영 |

### 저장 구조 (초안)
```
lumen_store: assess_<학교>_<학년>_<학기>     예: assess_옥길중_2_2026-2
{
  school:'옥길중', grade:2, term:'2026-2', subject:'수학',
  written: { ratio:60, exams:['중간','기말'] },
  perf: [
    { name:'서술형 평가', ratio:20, when:'10월 2주', elements:[...], criteria:'...' },
    { name:'탐구 보고서', ratio:20, when:'11월',     elements:[...], criteria:'...' }
  ],
  source:'학교알리미 공시 2026-09-30', by:'ai-vision', at:'...'
}
```

평가계획 파일을 그대로 읽어 과목별 지필·서답형·수행 표를 뽑는 구현이 이미 공개돼 있다
(soonryu74/soonryu74.github.io PR #41):

| 형식 | 읽는 방법 |
|---|---|
| HWP 5.0 | OLE/CFB 리더 + pako(raw inflate)로 본문 텍스트 추출 |
| HWPX · ZIP | JSZip + CP949 파일명 디코딩 |
| PDF | pdf.js |

서울 일반고 2026년 1학기 자료(ZIP 안 한글 13개)를 **13과목 전부 파싱 성공**.
전부 브라우저 안에서 처리되고 서버로 안 보낸다 → 우리 단일 HTML 앱 구조에 그대로 맞는다.
한계: 지원 안 되는 HWPX 서식은 "양식을 못 찾음"으로 빠진다.

### 🚧 넘어야 할 것
1. **파일을 어떻게 받나** — 학교알리미 OpenAPI는 인증키가 필요하고, 제공 항목은
   학교기본정보·학생/교원현황·급식·학업성취 등 **수치 데이터** 중심이다.
   **공시 첨부파일(hwp/pdf)을 API로 내려받을 수 있는지는 확인되지 않았다.**
   → 1차는 **원장님이 학교알리미에서 파일을 받아 앱에 올리는 방식**으로 시작.
     자동 다운로드는 나중에 확인 후 판단 (문의: schoolinfo@keris.or.kr)
2. **학교마다 양식이 제각각** — 표 구조가 통일돼 있지 않다. 파싱 후 **원장님 확인 단계 필수**
3. **학년·학기마다 다시** — 1년에 두 번(4월·9월) 갱신. 자동화보다 반자동이 현실적

### ⚖️ 범위 결정 — 전국 수집은 하지 않는다
다른 곳에서 **전국 중학교 3,500곳**을 자동 수집하는 사례를 봤으나(2026-09-20 원장님 제보),
그건 **입시정보 서비스 규모**다. 루멘수학에 필요한 것은 다르다.

| | 전국 수집 | **우리 방식** |
|---|---|---|
| 대상 | 중학교 3,500곳 | **학생들이 다니는 학교 10곳 안쪽** |
| 과목 | 전 과목 | **수학만** |
| 검수 | 불가능한 양 | 원장님이 눈으로 확인 가능 |
| 실패 시 | 조용히 틀린 데이터가 남음 | 바로 알고 손으로 고침 |

파일 10~20개면 파싱이 실패해도 감당된다. **작게 시작하는 것이 옳다.**

### ⛔ 선을 그어야 할 부분
수행평가는 **학생이 직접 수행해야 하는 평가**다.
- ✅ 되는 것: 평가 기준 정리·일정 안내, **서술형 연습 문제 생성**, 채점 기준에 맞춘 **자기 점검표**,
  준비 카드 배포, 학부모 안내
- ❌ 하면 안 되는 것: **탐구보고서·과제물을 대신 써주기.** 학생 제출물을 AI가 만들어주면
  학업 부정이고 학원 신뢰 문제로 직결된다. 기능 설계에서 처음부터 막아둘 것

### 왜 가치가 큰가
내신에서 수행평가 비중이 **보통 30~40%**인데, 대부분의 학원이 지필만 본다.
"우리 학원은 네 학교 수행평가 일정과 기준까지 알고 챙긴다"는 건 **학부모에게 바로 와닿는 차별점**이고,
블로그·인스타 글감으로도 강력하다 (아이디어 2번과 연결).

2. 잘 읽히면 저장 구조 확정 → 학원앱에 「수행평가」 탭
3. 칸반 연결(준비 카드) → 학부모앱 발행

## 🌱 6. 고교 비교 해설 리포트 — 진학 나침반 2단계

**등록일**: 2026-09-22 · **계기**: 원장님이 타 학원(지트인수학학원) 리포트 3쪽 PDF 제보

### 그 리포트가 하는 일
학교알리미 공시 데이터로 **고교 3곳을 나란히 비교 해설**한다.
쓰는 자료: 교과별 학업성취(절대평가 **A~E 비율**), 학년별 재적, 학급·교원 수, EDSS.

**분석의 핵심 (두 줄로 요약됨)**
- **A 비율이 높다 → 상위권이 두껍다 → 내신 경쟁이 치열하다**
- **E 비율이 높다 → 하위권이 넓다 → 상위권 진입이 상대적으로 쉽다**

예: 백영고 영어I A 42.4% → 실수 하나가 등급 하락. 동안고 수학I A 2.8%·E 35.2% → 실력만 있으면 1등급 여지.
"1등급 자리 = 1학년 재적 × 10%" (5등급제 기준, 지금 고1부터 해당).

**리포트 구성**: 학교 카드(재적·학급·교원) → 과목별 A~E 분포 → 학년별 추이(A비율·평균·E비율)
→ 한눈에 보기 → 5개 항목 별점 비교(내신 경쟁 강도·1등급 확보 여지·선택과목 폭·학력 수준·학종 환경)
→ 항목별 서술 → **학생 유형별 추천표**

### 루멘 진학 나침반과 겹치지 않는다 — 보완 관계
| | 루멘 진학 나침반 (이미 있음) | 이 리포트 |
|---|---|---|
| 묻는 것 | 이 아이가 저 고교 가면 **몇 등급** | 저 고교는 **어떤 구조**인가 |
| 입력 | 학생 성적 | 학교 공시 분포 |
| 답 | 예상 등급 | 어디가 유리한가, 왜 |

합치면: "범박고 3등급"에서 끝나지 않고 **"범박고는 수학 A가 두꺼워 빡빡하고, 소사고는 하위권이 넓어
네 강점이 등급에 더 잘 반영된다"**까지 말할 수 있다. 상담 설득력이 크게 올라간다.

### 필요한 것은 하나뿐
학원앱은 **이미 학교알리미 성적 분포를 쓴다** — 단 원장님이 화면을 캡처해 올리는 방식.
필요한 건 **부천 고교 예닐곱 곳의 과목별 A~E 비율을 API로 받아오는 것**.
전국 3,500곳은 필요 없다 (아이디어 5번의 범위 결정과 동일).
→ 성공하면 **캡처 작업 자체가 사라진다.**

### ⚙️ 어디서 돌리나 (중요)
클라우드 채팅은 학교알리미·공공데이터포털 접속이 **정책상 차단**돼 있다(403). 이건 어느 클라우드 채팅이든 같다.
**하지만 문제되지 않는다** — 수집기는 **GitHub Actions**에서 돌리면 된다. 그쪽은 차단이 없다.
매쓰플랫 수집기(`mathflat-collect.yml`)와 학사일정 수집기(`school-info.yml`)가 이미 그 방식으로 매일 돈다.

| 일 | 어디서 |
|---|---|
| 수집기 코드 작성 | 아무 채팅에서나 (클라우드 OK) |
| 실행·테스트 | **GitHub Actions** 또는 맥미니 |
| API 키 보관 | **GitHub Secrets** (`NEIS_KEY`와 같은 자리) |
